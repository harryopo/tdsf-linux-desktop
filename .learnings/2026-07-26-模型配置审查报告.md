## 2. 用户痛点根因

**用户的判断完全正确**：对话记录、KPI 统计、预算已用都是**无后端数据时的硬编码 fallback**。

启动日志证据（dev 期间）：
```
[2026-07-26T06:05:57.788Z] DEBUG [IPC.TOKEN] token:records {"limit":1000,"returned":0}
[2026-07-26T06:05:57.800Z] DEBUG [IPC.TOKEN] token:records {"limit":100,"returned":0}
[2026-07-26T06:05:57.796Z] DEBUG [IPC.TOKEN] token:stats {"today":0,"week":0,"month":0,"total":0}
[2026-07-26T06:05:57.798Z] DEBUG [IPC.TOKEN] token:cost-stats {"todayCost":0,...}
```

→ `token:records`/`token:stats`/`token:cost-stats` 全是 0（用户从未真实调用过 LLM）
→ 前端 `if (records.length === 0) return` 直接保留 `CONVERSATIONS` 假数据
→ 用户看到 5 条"假对话"+ 4 个 KPI 假数字，以为是真实历史

**深层问题不是"假数据"，而是"无数据时仍显示假数据"违反透明性硬约束**。

## 3. 修复方案

### 3.1 修复 A · 对话记录（删 CONVERSATIONS fallback）

**改动**：
- `constants.ts`: 删除 `CONVERSATIONS` 数组，改为导出 `EMPTY_CONVERSATION: ConversationRow[] = []`
- `ModelSettings.tsx:87`: `useState<ConversationRow[]>([])` 改为空数组
- `ModelSettings.tsx:143-179`: 删掉 `if (records.length === 0) return` 让 isLoading 状态正常切换
- 新增 `isLoadingRecords` 状态 + 空状态组件（"暂无对话记录，先在 AI 面板发消息"）

### 3.2 修复 B · KPI 4 项（删 DEFAULT_KPIS fallback）

**改动**：
- `ModelKpiBar.tsx:39-75`: 删除 `DEFAULT_KPIS` 数组
- 初始值改为 "—" / "$0" / "0 次" / "0%"
- sparkline 改为空数组或省略
- 新增 `isLoading` 状态，loading 时显示 skeleton
- 真实 IPC 数据返回后正常填充

### 3.3 修复 C · 预算"已用"（改读真实 cost-stats）

**改动**：

### 3.4 修复 D · 端到端验证
