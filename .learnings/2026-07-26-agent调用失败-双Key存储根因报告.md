# 2026-07-26 "Agent 调用失败" 双 Key 存储根因报告（v2.3.9）

## 现象

用户反馈：
- "连接大模型后还是显示 agent 调用失败"
- 在输入框输入内容发送后，仍显示"Agent 调用失败"
- 已重启应用，问题依旧

v2.3.8 已增强错误识别，把"Agent 调用失败"落地为具体错误码，但用户仍看到通用文案。

## 根因分析

### 1. 两套并行的 API Key 存储

| 通道 | 存储 key | 用途 | 配置入口 |
|-----|---------|------|---------|
| 旧 LLM 测试连接 | `llm`（settings-store） | `llm:test` IPC，仅验证连通性 | 设置 → 模型 → API 接入 → 测试连接 |
| Provider 系统 | `provider:${id}`（SecureStore） | `agent:chat` / Supervisor 实际调用 | 设置 → 模型 → 保存所有配置（隐式） |

**关键问题**：
- 用户在"测试连接"中输入 API Key 并点击"测试连接"，只验证 `llm:test` 通道
- `llm:test` 不会把 Key 同步到 Provider 的 SecureStore
- AI 对话主路径 `agent:chat` → Supervisor → `getProviderWithApiKey` 读取的是 `provider:${id}`
- 如果用户从未点击"保存所有配置"，或者保存时 `providers[0]` 逻辑没正确写入，`provider:deepseek-v4` 的 Key 为空
- `provider-factory.createLanguageModel` 用空 Key 调用 DeepSeek，返回 401/400，最终被吞成"Agent 调用失败"

### 2. 前端无保护

- `useAgentChat.ts` 的 `send` 函数不检查 selectedProvider 是否已配置 Key
- `Composer.tsx` 的 Provider 选择器不显示 Key 状态
- 用户无法区分"测试连接成功"和"AI 对话可用"

### 3. 为什么 v2.3.8 没解决

v2.3.8 只改进了**错误发生后的识别文案**，但：
- 如果错误根本没走到 `onAgentError`（例如 createLanguageModel 在调用前就因 Key 为空被拦截）
- 或者错误对象被包装后 message 仍是通用文案
- 用户看到的仍然是"Agent 调用失败"

真正的根因是**调用前未做 Key 存在性校验** + **测试连接与 Provider 配置不同步**。

## 修复方案（v2.3.9）

### 1. `src/shared/agent-types.ts` — 类型补齐

把 `PersistedProviderConfig` 从 `type` 改为 `interface`，附加可选 `hasApiKey?: boolean`：

```ts
export interface PersistedProviderConfig extends Omit<ProviderConfig, 'apiKey'> {
  /** 是否已配置 API Key（Ollama 本地无 Key 也视为 true；由 provider:list 运行时附加） */
  hasApiKey?: boolean
}
```

主进程 `provider-registry.listProviders` 本来就返回 `PersistedProviderConfigWithKey`（含 hasApiKey），现在前端类型也对齐了。

### 2. `src/renderer/src/components/workbench/useAgentChat.ts` — 调用前拦截

在 `send` 函数开头增加 Key 检查：

```ts
const state = useAgentStore.getState()
const selectedProvider = state.providers.find((p) => p.id === state.selectedProviderId)
if (selectedProvider && selectedProvider.hasApiKey === false) {
  message.warning(
    `当前模型 "${selectedProvider.name || selectedProvider.id}" 未配置 API Key，请到设置 → 模型中配置并保存`
  )
  return
}
```

效果：用户点击发送时，如果当前模型未配置 Key，直接弹出明确提示，不再调用 `agent:chat`，不再显示"Agent 调用失败"。

### 3. `src/renderer/src/pages/ModelSettings.tsx` — 测试连接成功后自动同步

在 `handleTestConnection` 的 `result.ok` 分支，自动调用 `providerSave`：

```ts
if (isElectronAPIAvailable() && providers.length > 0) {
  const defaultProvider = providers[0]
  await window.electronAPI.providerSave({
    ...defaultProvider,
    baseURL: endpoint,
    model: selectedModel,
    apiKey,
    defaultParams: {
      ...defaultProvider.defaultParams,
      temperature,
      maxTokens: maxToken,
    },
  })
  await window.electronAPI.providerSetDefault(defaultProvider.id)
}
```

效果：用户测试连接成功后，Key 立即同步到 Provider 系统，AI 对话直接可用，无需再点"保存所有配置"。

### 4. `src/renderer/src/components/workbench/Composer.tsx` — Provider 选择器显示 Key 状态

- 当前选中的 Provider 未配置 Key 时，按钮标签显示 `模型名 (未配置Key)`
- 下拉菜单中未配置 Key 的 Provider 显示红色 `(未配置Key)`、置灰、不可点击
- 增加 `title` 提示

效果：用户一眼就能看到当前模型是否可用，不会被"测试连接成功"误导。

## 用户操作指引

修复提交后，用户需要：

1. **拉取最新代码**（如果用户是独立运行，则直接当前工作区已是最新）
2. **重启应用**（已强杀旧 electron/node 进程）
3. 打开 **设置 → 模型**
4. 输入 API Key，点击 **测试连接**
5. 测试成功后，日志会显示 **"已自动保存到 Provider 配置"**
6. 返回工作台，底部 Provider 选择器不再显示 `(未配置Key)`
7. 在 AI 输入框输入内容发送，正常进入流式输出

如果用户仍看到 `(未配置Key)`：
- 说明测试连接没成功，或 providerSave 抛异常
- 看设置页测试日志的具体错误信息
- 或者手动点击 **保存所有配置**
