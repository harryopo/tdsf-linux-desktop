## 二、问题诊断与根因分析

### 问题 1：教程页 UI 白色背景

**根因**：`src/renderer/src/components/tutorial/TutorialPage.css` 中硬编码了白色背景
```css
/* 原代码（错误） */
.tutorial-page { background: #ffffff; }  /* 不跟随主题切换 */
.tutorial-card { background: #ffffff; }   /* 同上 */
.tutorial-sidebar { background: #fafafa; }  /* 同上 */
```

**修复策略**：将所有硬编码颜色替换为全局 CSS 变量（与 ServerList.css / ChatPanel.css 保持一致）。

### 问题 2：AI 发送按钮对齐错乱

**根因**：
- 使用了 `SendOutlined`（纸飞机）图标，与主流 ChatGPT/Claude 的"向上箭头"风格不符
- 输入框为多行 `TextArea`，按钮默认居中而非底部对齐
- 按钮尺寸为矩形（width/height 不固定），不美观

**修复策略**（参考 2026 主流 AI 对话界面调研）：
- 切换为 `ArrowUpOutlined`（向上箭头）
- 强制圆形：36×36px + `border-radius: 50%`
- 对齐方式：`align-items: flex-end` + `align-self: flex-end`

### 问题 3：爬虫源不显示

**根因**：
- 主进程 `tutorial:listSources` IPC handler 缺少错误处理，错误直接抛出
- 渲染进程未显示加载状态，UI 无反馈
- 爬虫源为空时缺少友好提示

**修复策略**：
- 主进程添加 try-catch + 详细错误日志（使用 logger）
- 渲染进程添加 `sourcesLoading` 状态、加载动画、错误提示
- 空源时显示 Alert 引导（指向日志路径）

### 问题 4：服务器配置未持久化

**根因**：
- `useServerStore` 只用 `zustand persist` 写入 localStorage
- localStorage 可能在某些场景被清空（用户清缓存、profile 损坏）
- 缺少从主进程加载的兜底机制

**修复策略**：实现**双重持久化策略**
- localStorage：快速 cache（已存在）
- 主进程 `electron-store`：权威持久化（新增）
- 启动时 `hydrateFromMain` 兜底加载
- 每次变更同步到主进程

## 三、技术方案

### 3.1 后端日志系统（核心基础设施）

**架构图**：
```
┌─────────────────────────────────────────────────────────────┐
│  渲染进程 (React)                                            │
│  logger.info('UI', '按钮点击') ──IPC log:renderer──┐        │
└─────────────────────────────────────────────────────┼────────┘
                                                     │
                                                     ▼
┌─────────────────────────────────────────────────────────────┐
│  主进程 (Electron)                                          │
│  Logger (单例)                                              │
│  ├─ console 输出 (带 ANSI 颜色)                              │
│  ├─ 内存 buffer (1000 条 FIFO)                              │
│  └─ 文件落盘 (logs/app-YYYY-MM-DD.log + .1.log 滚动)        │
│                                                             │
│  IPC Handlers:                                              │
│  ├─ log:read       — 条件过滤读取                            │
│  ├─ log:stats      — 统计信息                                │
│  ├─ log:flush      — 异步刷新                                │
│  ├─ log:clearBuffer — 清空内存                                │
│  ├─ log:setMinLevel — 动态调整级别                            │
│  └─ log:renderer   — 渲染进程上报入口                        │
└─────────────────────────────────────────────────────────────┘
```

**日志结构**（每条 JSON）：
```typescript
interface LogEntry {
  ts: string                    // ISO 8601 时间戳
  level: 'DEBUG' | 'INFO' | 'WARN' | 'ERROR' | 'FATAL'
  category: string              // 业务分类（IPC/SSH/LLM/CRAWLER/UI...）
  message: string               // 人类可读
  meta?: Record<string, unknown>  // 结构化数据
  correlationId?: string        // 跨调用追踪
  source: 'main' | 'renderer'  // 进程标识
  date: string                  // YYYY-MM-DD（按天切分用）
}
```

**关键能力**：
- **结构化**：每条 JSON，测试可机器解析
- **按天切分**：`app-YYYY-MM-DD.log`，7 天自动清理
- **大小轮转**：单文件 > 5MB 自动重命名为 `.1.log`
- **内存 buffer**：1000 条 FIFO（测试无需读文件）
- **可测试**：通过 IPC `log:read` 直接读取，毫秒级响应

### 3.2 渲染进程 Logger（薄封装）

`src/renderer/src/utils/logger.ts`：与主进程 logger 接口对齐

```typescript
import { logger } from '@/utils/logger'
logger.info('App', '从主进程加载完成', { count: 3 })
const uiLog = logger.child('ChatPanel')
uiLog.warn('输入框为空')
```

行为：
- 立即 console 输出（带颜色，便于开发）
- 异步 IPC 上报主进程（不阻塞 UI）
- IPC 不可用时降级为 console-only
- 失败计数 `getFailedUploadCount()` 用于自检

### 3.3 双重持久化策略

**数据流**：
```
UI 变更
  ├─→ zustand state (内存) ← React 订阅立即生效
  ├─→ zustand persist (localStorage 缓存) ← 防 IPC 频繁往返
  └─→ IPC server:save (主进程) ← 权威持久化（safeStorage 加密敏感字段）
```

**启动加载**：
```
App 启动
  └─→ useServerStore.hydrateFromMain()
       ├─ localStorage 有数据 → 以 localStorage 为准，回写主进程
       ├─ localStorage 无 + 主进程有 → 用主进程
       └─ 都没有 → 空状态
```
