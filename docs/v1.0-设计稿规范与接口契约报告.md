## 一、项目定位与整体架构

### 1.1 项目定位

TDSF Linux 运维教学一体平台（Trusted Decision Support Framework for Linux Operations）是 **2026 火山杯 Agent 创新大赛参赛作品**，定位为面向 Linux 运维场景的 **可信决策支持桌面助手**。核心差异化卖点：

1. **D-S+PCR5 证据理论算法**：Dempster-Shafer 证据合成 + PCR5 冲突重分配，6 源证据融合（指标采集 / 历史匹配 / 知识库 / 人工校验 / 模型置信 / 基础分）。
2. **HITL 七步证据链**：collect → analyze → reason → check → confirm → execute → verify，全链路人工审批闸门。
3. **IDE 化运维工作台**：文件树 + 编辑器 + 终端 + AI 对话四栏一体，借鉴 TRAE / VS Code 工作台美学。
4. **四层风险控制**：L1 白名单 / L2 高危拦截 / L3 沙箱预演（OpenHands/Docker）/ L4 人工确认。

### 1.2 整体架构

设计稿采用 **Electron 三层架构 + 渲染层 React 18 + AntD 5**：

```
┌────────────────────────────────────────────────────┐
│ 渲染进程 (React 18 + AntD 5 + Zustand + xterm.js)  │
│   ├─ 9 个 Zustand Store                            │
│   ├─ 39 个 UI 组件（9 个分类目录）                  │
│   └─ window.tdsf.* preload 白名单 API              │
├────────────────────────────────────────────────────┤
│ Preload (contextIsolation + sandbox)               │
│   └─ IPC 4 步同步：定义→注册→暴露→d.ts 类型         │
├────────────────────────────────────────────────────┤
│ 主进程 (Electron 28+ + Node.js)                    │
│   ├─ 22 个 IPC 模块 (89 个 IPC 通道，v0.9.5 盘点)  │
│   ├─ 核心服务：SSH / SFTP / Sandbox / LLM / KB     │
│   └─ 可信度引擎：D-S + PCR5 + 6 源证据              │
└────────────────────────────────────────────────────┘
```

**技术栈**：Electron 28+ / React 18 / AntD 5 / TypeScript 5 严格模式 / Vite 5 / Zustand / React Router v6 Data Router / xterm.js + addons / @monaco-editor/react / TRAE 120 SVG 图标库。

### 2.2 字体系统

| 类别     | 字体栈                                                      |
| -------- | ----------------------------------------------------------- |
| 正文字体 | `"SF Pro Text", "Microsoft YaHei", system-ui, sans-serif` |
| 代码字体 | `"JetBrains Mono", "Cascadia Code", Consolas, monospace`  |

**硬约束**：font-family 栈必须包含 `"Microsoft YaHei"` 且位于 `system-ui` 之前；任何情况下禁止出现宋体（SimSun / STSong / FangSong / SongTi）。

字号层级（紧凑 IDE 密度）：3xs(11px) / 2xs(12px) / xs(10px) / sm(12px) / base(13px) / lg(14px) / xl(16px) / 2xl(20px) / 3xl(32px)，强字重 `*-strong` 为 500。

### 2.3 间距系统

`0 / 4 / 6 / 8 / 12 / 16 / 24 / 32 / 40 px`，紧凑 IDE 工作台密度。

### 2.4 圆角系统

`2 / 4 / 6 / 8 / 10 px`（小而克制，避免圆润 Mac 风），状态点 / 进度条 `9999px`。

**侧边色条特殊样式**（用户强偏好）：左侧直角矩形竖条 `border-radius: 0 6px 6px 0` + `border-left: 2px solid`，禁止 `border-radius: 6px` + `border-left` 的四角圆角包裹色条样式。

### 2.5 阴影与深度

不使用重阴影。深度通过 `bg-base-secondary` / `bg-base-tertiary` + `overlay-l1~l4`（实色 hex）分层表达。

### 2.6 图标系统

- **来源**：TRAE 120 SVG 图标库（`assets/icons/dl_builtin_trae/{name}.svg`）
- **渲染方式**：CSS `mask` 属性（`mask-image: url(...)` + `mask-size: contain`）
- **线宽**：2px stroke
- **关键图标**：terminal / cpu / dashboard / server-via-box / shield / alert / bell / check-circle / zap / sparkles / send / message-circle / home / settings / history-via-clock / book / chevron-right / arrow-right / plus / search / refresh / trending-up / trending-down / activity-via-bar

### 2.7 动画规范

- **基础过渡**：200ms ease-out，hover 仅 `bg-overlay` 轻微提亮（不位移 / 不缩放）
- **加载动画**：粒子汇聚（boot 启动页 Three.js shader 流光动画）
- **`prefers-reduced-motion`**：禁用进度条 / 按钮脉冲 / 入场动画（shader 核心视觉保留）
- **决策进行中**：脉冲虚线动画

### 6.2 6 源证据数据模型（C1 修复后）

```typescript
interface EvidenceSource {
  sourceId: 'metric' | 'history' | 'knowledge' | 'human' | 'model' | 'base'
  sourceName: string  // 指标采集 / 历史匹配 / 知识库 / 人工校验 / 模型置信 / 基础分
  sourceType: 'base' | 'positive' | 'negative'
  weight: number      // 权重 0-1
  score: number       // 得分 0-1
  confidence: number  // 单源置信度 0-1
  evidence: object    // 证据详情（命令输出 / 日志片段 / KB 引用等）
  timestamp: string   // ISO 8601

```

### 6.3 D-S+PCR5 计算公式

```
m_combined(A) = Σ m_i(A) * Π m_j(B) / (1 - K)    （D-S 合成）
                                            ⌃
PCR5 冲突重分配：m_conflict(A) = Σ_{i≠j} [ m_i(A)^2 * m_j(B) / (m_i(A) + m_j(B)) ]
                                       ⌄
最终置信度：m_final(A) = m_combined(A) + m_conflict(A)
```

### 6.4 9 态审批状态机（C2 修复后）

```
suggested ──user review──> pending_approval ──approve──> approved ──> executing ──> success
                                  │                          │            │
                                  ├──reject──────────────────>│rejected   │failed
                                  │                           │            │
                                  └──modify───────────────────>│modified   ▼
                                                                         rolled_back
            [30 秒超时自动 reject]                            [失败可回滚]
```

`VALID_TRANSITIONS` 表驱动，禁止非法状态跳转（如 `suggested → executing` 不允许）。

## 七、交互流程

### 7.1 SSH → 工作台 → AI → 审批 → 执行 主流程

```
1. 用户点击"新建连接" → ConnectDialog 弹窗
2. POST /api/servers → 保存服务器（凭证 safeStorage 加密）
3. WS /api/ssh/connect → 建立 SSH 连接 → ssh:connected 事件
4. 进入 workbench-ai.html（三栏 IDE 工作台）
5. 用户在 chat-composer 输入自然语言需求
6. SSE /api/ai/chat 流式响应：
   - chat:thinking → 思考过程
   - chat:tool_call → 工具调用（如 ssh exec / file read）
   - chat:tool_result → 工具结果
   - chat:evidence → 6 源证据推送
   - chat:decision → 决策建议
7. POST /api/decision/confidence → D-S+PCR5 计算 → 返回置信度
8. 决策卡片显示 suggested 状态 + 批准/拒绝/修改按钮
9. 用户点击批准 → POST /api/decision/confirm → approved
10. 进入 executing → L3 沙箱预演（OpenHands Docker）
11. 沙箱通过 → 真实 SSH 执行 → success / failed
12. 失败可触发回滚 → rolled_back
13. 决策记录入库 → POST /api/decision/history
```

### 7.2 关键状态机时序

- **审批闸门位置**：决策卡片 `suggested` → 用户操作 → `pending_approval`（30 秒倒计时）→ `approved/rejected/modified` → `executing` → `success/failed`
- **超时处理**：`pending_approval` 30 秒自动 `rejected`，UI 显示"超时未确认，已自动拒绝"
- **回滚机制**：`executing` 失败 → 用户主动触发 → `rolled_back`（执行前已保存状态快照）

## 九、关键约束与规范

### 9.1 安全约束（硬约束）

1. **Electron 三层安全**：`contextIsolation: true` + `sandbox: true` + CSP 严格策略
2. **凭证安全**：SSH 密码 / API Key 通过 Electron `safeStorage` 加密存储，明文永不下发渲染进程
3. **敏感文件 redact**：`.env` / `.ssh/` / `*_key` 发送前自动脱敏
4. **网络请求可见性**：所有网络请求在 UI 可见（借鉴 Grok Build 数据丑闻教训）
5. **IPC 4 步同步铁律**：定义（main）→ `ipc/index.ts` 注册 → `preload` 暴露 → `electron.d.ts` 类型声明，缺一不可
6. **JWT 鉴权**：所有 REST 接口（除 `/api/auth/login`）必须携带 `Authorization: Bearer <jwt>`
7. **请求签名**：高危操作（`/api/decision/confirm` / `/api/servers/:id/delete`）必须携带 `X-Signature` HMAC 签名

### 9.2 性能约束

| 维度          | 约束                                                 |
| ------------- | ---------------------------------------------------- |
| 首屏加载      | < 2 秒（Vite 5 分包 + lazy 路由）                    |
| 终端输入延迟  | < 50ms（xterm.js WebSocket 直连）                    |
| AI 首 token   | < 1.5 秒（SSE 流式）                                 |
| 监控指标推送  | 1 秒间隔（WS 流）                                    |
| 日志列表      | 万级日志必须虚拟滚动（react-virtual），固定行高 32px |
| D-S+PCR5 计算 | 放入 Web Worker，避免阻塞主线程                      |
| Electron 窗口 | `minWidth: 1024, minHeight: 680`                   |

### 9.3 兼容性约束

- 桌面端优先（Electron Win/Mac/Linux）
- 响应式断点：`≥1440px` 三栏 / `1024~1440px` AI 面板收窄 / `768~1024px` AI 抽屉化 / `<768px` 不推荐
- 字体栈必须包含 `"Microsoft YaHei"` 且位于 `system-ui` 之前（防 Windows 中文宋体回退）

### 9.4 可访问性约束

- 所有交互元素必须有 `aria-label`
- 告警颜色不能作为唯一信息维度（需配合图标 + 文字）
- `prefers-reduced-motion` 必须禁用进度条 / 按钮脉冲 / 入场动画
- 键盘导航支持（Tab 顺序 + Enter 触发 + Esc 关闭弹窗）

### 9.5 IPC 4 步同步规范

每次新增 IPC 通道必须完成：

1. **定义**（`src/main/ipc/<module>.ts`）：`ipcMain.handle('xxx:yyy', handler)`
2. **注册**（`src/main/ipc/index.ts`）：`registerXxxHandlers(mainWindow)`
3. **暴露**（`src/preload/index.ts`）：`xxxYyy: () => ipcRenderer.invoke('xxx:yyy')`
4. **类型声明**（`src/preload/electron.d.ts`）：`xxxYyy: () => Promise<ResultType>`
