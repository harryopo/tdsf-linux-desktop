## P0 关键问题 (影响核心功能)

### P0-1. 每日决策归档 — 占位 handler

**位置**: `src/main/services/scheduler/daily-decision-archive.ts:465-482`

**问题**: `createDailyDecisionArchiveTask()` 工厂返回占位 handler,每日 18:00 触发时输出 `console.warn` 并返回空数据,不归档任何决策。

**影响**: 决策历史不会自动归档,Phase 7 前定时任务形同虚设。

**修复方案**:
```typescript
// 使用 createDailyDecisionArchiveTaskWithRepos(decisionRepo, knowledgeRepo)
// 替代默认工厂,注入真实 repository
```

**优先级**: ⚠️ Demo 可接受,生产必须修复

---

### P0-2. 运维周报 — 占位仓储返回空统计

**位置**: `src/main/services/scheduler/weekly-ops-report.ts:415-471`

**问题**: `PlaceholderDecisionRepo` 和 `PlaceholderKnowledgeRepo` 直接返回全零统计:
```typescript
getWeeklyStats() {
  console.warn('使用占位仓储')
  return { total: 0, successCount: 0, blockedCount: 0, ... }
}
```

**影响**: 运维周报不含真实数据,用户看到的是空壳报告。

**修复方案**: 注入 `DecisionRepo` 和 `KnowledgeRepo` 实例,实现真实统计查询。

**优先级**: ⚠️ Demo 可接受,生产必须修复

---

### P0-3. MCP 知识库资源 — 始终返回占位 Markdown

**位置**: `src/main/services/mcp/resources.ts:188-289`

**问题**: `readKnowledgeResource()` 在数据库不可用/无匹配/读取失败时调用 `renderKnowledgePlaceholder()`,返回含 `⚠️ 占位内容(TODO 真实集成)` 的 Markdown。

**影响**: MCP 客户端(Claude Desktop)读取知识库资源时看到占位提示而非真实知识。

**修复方案**:
1. 确保知识库种子数据加载到 SQLite
2. 实现 `queryKnowledgeBase()` 真实查询逻辑
3. 移除占位渲染分支

**优先级**: ⚠️ 影响 AI 上下文获取,建议第一周修复

---

### P0-4. Mastra Ops Agent — API Key 硬编码降级

**位置**: `src/main/core/agent/mastra/ops-agent.ts:101`

**问题**: 当 `llmConfig.apiKey` 为空时用字符串 `'placeholder'` 作为 API Key:
```typescript
apiKey: llmConfig.apiKey || 'placeholder',
```

**影响**: Mastra Agent 在无 API Key 时发送带假 Key 的请求,导致 401 错误而非明确报错。

**修复方案**:
```typescript
if (!llmConfig.apiKey) {
  throw new Error('Mastra Agent 需要配置 API Key')
}
```

**优先级**: ⚠️ 影响错误排查,建议立即修复

---

### P0-5. OpenHands batchGetSandbox — API 端点预留未实现

**问题**: REST API 路由表标注了 `batchGetSandbox` 端点但代码不存在实现。

**影响**: 如有上层调用方会直接报方法不存在错误。

**修复方案**:

**优先级**: ⚠️ 沙箱批量查询不可用,按需实现

## P1 重要问题 (功能降级/设计债务)

### P1-1. Claude SDK Provider 缓存清理未实现

**位置**: `src/main/ipc/claude-sdk.ts:96`

**问题**: `providerCache` Map 在 Provider 配置保存后不会被清理,用户修改设置后旧实例仍被使用直到重启。

**影响**: 修改 Claude SDK Provider 配置后不生效,需重启应用。

**修复方案**:
```typescript
// provider:save 事件处理中添加
providerCache.clear()
```

---

### P1-2. Edit 策略 patch 格式未实现

**位置**: `src/main/core/agent/edit-formats/strategy-selector.ts:38`

**问题**: Edit 策略只有 `editblock | whole-file | udiff` 三种,patch 格式(V4A)被推迟到 v0.9.5。

**影响**: 局部补丁编辑能力缺失。

**修复方案**: 实现 `patch-strategy.ts` 支持 diff-patch 格式。

---

### P1-3. MCP Prompts 未知 ID 抛错

**位置**: `src/main/services/mcp/prompts.ts:162`

**问题**: 请求不在 5 个预定义 ID 之外的 prompt 时直接抛异常,而非优雅降级。

**影响**: MCP 客户端收到错误响应而非友好提示。

**修复方案**: 返回 `null` 或默认 prompt,让客户端自行处理。

---

### P1-4. PAOR 循环人工审批交互延后

**位置**: `src/main/ipc/agent-runtime.ts:366`

**问题**: PAOR 自主循环中高危命令自动拦截,但审批交互被推迟。当前自动拒绝,用户无法在循环中批准执行。

**影响**: PAOR 循环遇到高危命令一律拦截,无法让用户确认后继续。

**修复方案**: 接入 `sandbox:approval-request` 通道,实现审批弹窗。

---

### P1-5. VercelAiService 降级丢失 Token 统计

**位置**: `src/main/services/llm/vercel-ai-service.ts:173-181`

**问题**: 降级到 `LlmClient` 时 Token 用量全部为 0,`finishReason` 为 `'fallback'`。

**影响**: Token 统计功能在降级路径下完全失效。

**修复方案**: 在降级路径中估算 Token 数(按字符数 / 4 计算)。

---

### P1-6. DatabaseManager mock Statement 回退

**位置**: `src/main/services/db/database.ts:201-217`

**问题**: 当 `better-sqlite3` 加载失败时 `prepare()` 返回 mock Statement,`run()` 返回 `changes: 0`,写入操作静默失败。

**影响**: 数据库不可用时所有读写操作静默失败,可能导致数据丢失假象。

**修复方案**: mock Statement 的 `run()` 应抛出明确错误而非静默返回空。

---

### P1-7. Credibility 6 源权重降级方案

**位置**: `src/main/ipc/credibility.ts:167-173`

**问题**: 权重应用并非真正的加权融合,而是在最终 confidence 上做简单线性调整。注释标注为"降级方案"。

**影响**: 用户配置的权重未真正生效,实际效果与配置不符。

**修复方案**: 在 `fusion-engine.ts` 中实现 6 源加权融合(D-S 理论完整版)。

---

### P1-8. sandbox-approval 回滚命令硬编码占位

**位置**: `src/main/ipc/sandbox-approval.ts:273`

**问题**: `/etc/` 文件修改的回滚命令是硬编码的 `xxx.bak` 模板字符串:
```typescript
return '从备份恢复:cp /etc/xxx.bak /etc/xxx(建议操作前先备份)'
```

**影响**: 用户看到的回滚建议不可直接使用。

**修复方案**: 基于实际命令生成回滚建议(解析目标文件路径)。

---

### P1-9. 教程 embedding 回填同步阻塞无进度推送

**位置**: `src/main/ipc/tutorial.ts:259`

**问题**: 2578 条教程的 embedding 回填是同步阻塞的(1-3 分钟),无进度事件推送。

**影响**: 首次回填时 UI 冻结,用户无法知道进度。

**修复方案**:
1. 改为异步分批处理
2. 推送 `tutorial:backfill-progress` 事件

## 设计降级链路汇总 (有意设计,非 bug)

以下是代码中**有意设计的降级链路**,虽非 bug 但值得跟踪:

| 降级链路 | 文件 | 说明 |
|---------|------|------|
| VercelAiService → LlmClient | `vercel-ai-service.ts` | API Key 为空或调用失败时降级 |
| LlmClient → rule-engine | `client.ts:448-472` | LLM 调用/解析失败降级到规则引擎 |
| AST risk-engine → regex | `risk-engine-ast.ts:273` | WASM/AST 解析失败降级到正则 |
| sqlite-vec → FTS5 → LIKE | `database.ts:246-649` | 向量搜索逐级降级 |
| Embedding → FTS-only | `tutorial-repo.ts:513` | 模型不可用时仅用全文检索 |
| Drain3 → 本地正则 | `drain3-bridge.ts:148-149` | Python 进程不可用时降级 |
| Langfuse → 本地日志 | `langfuse.ts:79` | 无 API Key 时禁用 trace |
| D-S/PCR5 → 简单规则 | 架构层面 | Demo 阶段简化路径 |
| CoT trace → text-fallback | `cot-trace-collector.ts:343` | 无 ThinkingBlock 时用句子切分 |
