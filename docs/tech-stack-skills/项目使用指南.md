## 5. 项目技术栈选型决策树

```
是否需要复杂业务组件（Form/Table/Tree）？
  ├─ 是 → Antd
  └─ 否 → 是否设计稿严格 1:1 复刻？
            ├─ 是 → shadcn + Tailwind + CVA
            └─ 否 → Antd 或 shadcn 二选一

是否需要状态管理？
  ├─ 跨组件共享 → Zustand
  ├─ 浏览器侧事件流 → Dexie
  ├─ 主进程业务数据 → better-sqlite3
  ├─ 配置 / 窗口状态 → electron-store
  └─ 凭据 → SecureStore（加密）

是否需要虚拟化列表？
  ├─ 简单（< 1000 项）→ 不用
  └─ 复杂（> 1000 项）→ react-window + react-virtuoso

是否需要编辑器？
  ├─ 是 → @monaco-editor/react（必用）
  └─ 否 → -

是否需要终端？
  ├─ 是 → @xterm/xterm + WebGL
  └─ 否 → -
```

## 6. 实战开发工作流（端到端）

### 6.1 添加新功能模块

```
[1] 调研：先查 SKILL-CATALOG-v1.0.md + tech-stack-skills/ 对应章节
[2] 方案：用 writing-plans 写实施计划
[3] 数据模型：设计 SQLite 表（zod 校验）
[4] IPC 通道：4 步同步（定义 → 注册 → preload → d.ts）
[5] Store：Zustand 一模块一 Store
[6] 组件：shadcn 优先 / Antd 兜底
[7] 测试：Vitest 单元 + Playwright E2E
[8] 验证：verification-before-completion 必跑
```

### 6.2 修复 bug

```
[1] 复现：systematic-debugging Skill
[2] 定位：查对应技术栈章节（场景速查表 §1）
[3] 修复：参考 best practices
[4] 测试：加 regression test
[5] 验证：跑编译门禁（typecheck:node + typecheck:web + lint）
[6] 提交：git-commit Skill
```

### 6.3 升级技术栈版本

```
[1] 查官方 changelog（context7 Skill）
[2] 评估 breaking change（搜 LRN-20260720-006 类踩坑）
[3] 写 spec：方案书（writing-plans Skill）
[4] 实施：分阶段提交（小步快跑）
[5] 验证：编译 + 测试 + E2E
[6] 归档：更新 DEV_SKILLS.md + tech-stack-skills/
```

## 7. 质量门禁（提交前必跑）

```bash
# 1. TypeScript 双端类型检查
pnpm typecheck:node   # 主进程 + 预加载
pnpm typecheck:web    # 渲染层

# 2. ESLint
pnpm lint

# 3. 单元测试
pnpm test

# 4. E2E 测试
pnpm test:e2e

# 5. 完整 build
pnpm build
```
