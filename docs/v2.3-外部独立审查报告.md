## TL;DR 一句话评价

**这是一个把"如何管理 AI 写代码"做成产品的项目——457 个源文件、193 个 IPC 通道、1,387 行 AI 行为规范、92 个依赖、6,766 行归档文档、3 个 Python Sidecar——但 33% 的 commit 都在写文档而不是写功能。打一个比喻：你开了一家餐厅，但大部分时间都在写菜谱和厨房管理手册，顾客连门都还没进。**

## TOP 5 致命问题

### 问题 1: 规范体系自我瓦解——"犯规了写个 WIP 标签就没事"

- 严重级别：🔴致命
- 证据：CLAUDE.md B1-B10 全部允许 `// WIP:` 绕过，AGENTS.md 第 500 行："规范是用来帮助开发的，不是用来阻碍开发的"
- 根因：团队在"AI 不听话"和"AI 太听话"之间反复摇摆。v1.0 全标 A 红线→AI 不敢动；v2.4 降为 B 级→所有约束变成可选的
- 修复建议：只保留 3 条 A 红线，其余转为 ESLint 规则 + CI 门禁硬编码
- 如果不管：3 个月后 `// WIP:` 成为团队通用语，"这个 WIP 了没"取代代码审查

### 问题 2: preload/index.ts 3,283 行——单一故障点

- 严重级别：🔴致命
- 证据：preload 聚合 193 个 IPC 调用于一个文件，B4 字面量约束允许 WIP 绕过
- 根因：审计→归档→遗忘循环，v2.2 标记 P1 后无人修复
- 修复建议：本周强制拆分为 19 个域子模块
- 如果不管：preload 错误会导致整个 Electron 窗口白屏，无错误边界

### 问题 3: 循环工程自噬——33% 的 commit 是"归档"

- 严重级别：🔴致命
- 证据：最近 30 个 commit 中 10 个是归档/文档（33%）；5 个归档目录共 6,766 行
- 根因：AGENTS.md 评分中"文档同步"占 15% 权重——写文档比写代码更划算
- 修复建议：删除归档五件套，合并为 CHANGELOG.md
- 如果不管：3 个月后 docs/ 超过 150 个文件，LEARNINGS.md 超 500 条，没人读完

### 问题 4: 92 个依赖 + 3 个 Python Sidecar = 产品定位失控

- 严重级别：🔴致命
- 证据：依赖列表含 Mastra + Vercel AI SDK（两个 Agent 框架共存）、three.js 3D 渲染、EU AI Act 合规审计、D-S 证据理论 + PCR5 + ECE 校准
- 根因：比赛叙事驱动堆叠技术栈，借鉴 18 个开源项目，没问"Linux 教学工具真的需要这些吗"
- 修复建议：砍掉 Python Sidecar（至少砍 2 个）、砍掉 EU AI Act 合规、砍掉 three.js
- 如果不管：安装包 >600MB，冷启动 8 秒，评委看了一眼就关掉

### 问题 5: "质量优先"是口头禅，没有度量标准

- 严重级别：🔴致命
- 证据：A7 说"质量绝对优先"，B1 说"不强制 ≤500 行"——35 个文件超 500 行。v2.2 审计修复率仅 19%（68→13）
- 根因：A7 没有任何可验证的度量指标
- 修复建议：ESLint max-lines ≤600、CI 覆盖率 ≥70%、冷启动基测 <3s
- 如果不管：熵增闭环——审计发现问题→记录→降低标准→下次审计标准更低

## 规范批判

### 合理的规范
- A1 IPC 4 步同步铁律（真实安全需求）
- A3 catch 块脱敏（SSH 凭据泄露风险）
- C1 DEV 模式 sample data（合理开发体验）

### 应删除的规范
- **A4 诚实标注未完成**——如果流程需要"禁止撒谎"作为正式规则，流程已经崩了
- **B5 UI 选型决策树**——21 行规则表让 AI 记住 7 种存储方案区别，不如用脚手架代码
- **A9 技术栈 Skill 调用前置**——触发条件精确到"≥50 行新代码"，但谁在数行数？

### 互相矛盾的规范
- A7 "质量优先" vs B1 "不强制 ≤500 行" → 0 约束
- A6 "每个 Task dispatch reviewer" vs AGENTS.md "单 AI 模式" → 自己审自己
- AGENTS.md "规范不阻碍开发" vs CLAUDE.md A5 "动工前先查 skill" → 听谁的？

### 还缺的规范
- 打包/发布规范（build:win 跳过 2+ 版本但无双基门禁）
- 性能基测规范（冷启动/内存/CPU 无任何指标）
- 功能废弃/移除规范（48 处 mock 永远不被替换）

## 流程批判

### 核心反模式
1. **归档优先于交付**——每个 Phase 交付的是"归档五件套"而非可运行软件
2. **审计→归档→遗忘循环**——v2.2 审计 68 个问题只修 13 个（19%），归档后旧问题仍在
3. **量化评分崩塌**——AGENTS.md 评分标准看上去科学（7 维 100 分），但没有可执行的计算规则

### commit 质量分析
| 类型 | commit 数 | 占比 |
|------|----------|------|
| feat | 12 | 40% |
| fix | 5 | 17% |
| docs（归档） | 10 | 33% |
| refactor | 3 | 10% |

**33% 的 docs 占比是明显异味，健康项目应在 5-10%。**

### 归档文档价值评估
6,766 行中约 50-60% 是元数据重复（方案书副本、审计报告副本）。有长期价值的不超过 2,000 行。
**5 个归档目录可以合并为 1 个 CHANGELOG.md。**

**功能合理性分析：**
- ✅ SSH 终端 + AI 辅助 + 风险控制 + 决策卡片 = 4 项核心功能
