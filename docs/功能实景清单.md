## B 组 · 有条件可用（功能在，缺外部条件）

| 能力 | 缺什么 | 缺的时候界面什么样 |

| 远程日志 tail、SFTP、端口转发、监控采样 | 一台连得上的 Linux 服务器 | 空状态，不放示例数据 |

## C 组 · 断线（有实现、有测试，生产链路零调用）

统计口径：preload 暴露 **271** 个键，其中 **141 个在 `src/renderer` 里零引用**（2026-10-20 实测）。
上一拍记的是 128——一天之内涨到 143 而没有任何人发现，因为它原先只是 INFO、不阻断。
现在 `pnpm audit:ipc` 把它钉成只降不升的刻度（`UNUSED_CAP = 141`，CI 里跑）：
新增一个"后端有、前端没人按"的键会直接红；负向对照验过（把刻度改成比实测小 1 立刻 rc=1）。
knip 查不出这一层（它把 preload 当 entry，只看引用不看调用），所以这条数只能靠通道面反查。

下面这些**不要**当成「可用功能」介绍给任何人：

- **Subagent 调度器**：8 个 Subagent 在 `supervisor.ts:337` 被实例化，但 `subagents/dispatcher.ts`
  的 8 步调度只被 `subagents/index.ts` 转出、生产零调用点（只有两个访问器）。
  原先并列的"14 步 Task Protocol"与它那套 `task-sediment` / Task Permission 审批已按下面那条口径
  **整删**（2026-10-20：实现 7 个文件 + `task-permission-approval.ts` + `TASK` 通道 + preload 两把键 +
  5 个测试文件 + `shared/approval-types.ts` 里三个形状），代码只留在 git 历史。
- **旧 AgentWorkflow 与裸 llm 通道**：`ipc/agent.ts` + preload `agentStart/agentConfirm`、`preload/index.ts:138-142` 的 `llmChat` 全家。
- **@命令解析**：`core/agent/at-commands/*` + `ipc/at-commands.ts:125`（Composer 里的 `injectedAtCommand` 是另一套实现，`Composer.tsx:127`）。
- **五模式**：`ipc/mode.ts:92-168` 无 UI；mode-registry 只被上面那条死路径和 `mcp/resources.ts:323` 读。
- **attention 追踪 / expectation 监控 / deploy / promptfoo**：`ipc/attention.ts:78-239`、`ipc/expectation.ts:65`、`ipc/deploy.ts:33-111`、`ipc/promptfoo.ts:36-68`。
- **MCP 应用内管理面**：`ipc/mcp.ts:79,94` 与 preload 的 5 个 `mcp*` 键无引用（渲染层只有工具卡分类）。
- **查询类通道无人调**：diagnostics 6 条、profiler 4 条（只作为 AI 工具活着）、sftpSearch/sftpGrep、kbDelete/kbImport、
  serverExport/Import、storageDeleteApiKey、riskCheck（`AIPanel.tsx:247` 记着是故意撤的）、logFlush/logSetMinLevel、
  terminalCompletionImport、systemPing/getProtocolVersion/tokenReset、tutorial 爬取回填 14 键、sidecar 启停健康 7 键、memory 4 键。

**这些债的处置口径**：要么补上生产调用点并在这里升回 A/B 组，要么整删（实现 + 通道 + 预加载键 + 测试 + 文案）。
不许停在「代码在、测试绿、只是没人按」的半态——那会让下一个接手的人以为能直接用。

```bash

# IPC 通道面：请求-响应 / 事件推送两条口径

# 闸的覆盖面：四个出口是否都过 evaluateCommand
npx vitest run tests/unit/command-gate.test.ts tests/unit/xterm-osc-return-false.test.ts

npx tsx scripts/audit-ipc-contract.ts
```

## 维护规矩

1. 新能力进这份文档的前提是**有生产调用点**；只有测试引用的写进 C 组，不写进 A 组。
2. 每组结论都要留 `file:line`；行号漂了由 `doc:links` 与代码审查负责抓，不由记忆负责。
3. 数字只有一个出口：`npm run promo:check`。这份文档里出现任何统计值，都要能指回一条命令。
