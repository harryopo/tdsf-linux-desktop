### 命令风险闸

判定只有一个入口：`src/main/core/command-gate.ts:768 evaluateCommand`
（结构性拦截器 8 条在 `:95-104`，argv 规则与词表项由 `scripts/quality/promo-readout.mjs` 现场数）。

命令闸管的四个出口都过闸：

- 远程 exec：`src/main/ipc/ssh.ts:350`
- 交互键入（攒到回车整行判）：`src/main/ipc/ssh.ts:20` 的 LineGate、本机终端同口径 `src/main/ipc/local-terminal.ts:20`
- AI 提议的写命令与只读命令：`src/main/core/agent/supervisor.ts:828`（与终端键入同一个 `evaluateCommand`）

**第五个出口走的是另一种控制（#173 接上）**：渲染层直连外部 MCP server 的 `mcp:external-call`
（`src/main/ipc/mcp.ts:94`）不套 `assessToolCall`，而是**每次调用都要人工批准**
（`src/main/ipc/mcp.ts:102` → `src/main/core/security/approval-request.ts`，60 秒无人回答＝拒绝，
拒绝会进同一条拦截留痕）。原因是那道闸按工具名查形状表、查不到就整条拒，
而第三方服务器的工具名不可枚举——接上去等于把所有外部工具拒死；
参数是不是 shell 命令也只有对面那个服务器知道，判不了就先问人。
真机判据：`tests/e2e/mcp-external-call-approval.spec.ts`（渲染层直接发起调用 → 审批卡真的出现 →
点拒绝 → IPC 回 `not-approved`；把审批摘掉这条就红）。
界面入口在 2026-10-25 补上了：设置 → 外部 MCP 的每个工具行带一颗「试调用」（#217），
填 JSON 参数→执行，走的还是上面这条同一出口，所以用户自己也能拿真工具验一次审批拦不拦得住。
判据：`tests/components/pages/mcp-settings-tool-call.test.tsx` 五条（含"参数不是合法 JSON 一个请求都不发"
与"没批准那张脸不许长得像回了话"），真机那遍在 `tests/e2e/mcp-external-settings.spec.ts` 第 ⑤ 步
（拒一次→界面写"没有执行"；批一次→界面显出对面回的文本）。
详见 §C 组与 `docs/长期优化目标.md`。

规则本身在界面可读：`src/renderer/src/pages/RiskSettings.tsx:111`（只读快照）。

## 维护规矩

1. 新能力进这份文档的前提是**有生产调用点**；只有测试引用的写进 C 组，不写进 A 组。
2. 每组结论都要留 `file:line`；行号漂了由 `doc:links` 与代码审查负责抓，不由记忆负责。
3. 数字只有一个出口：`npm run promo:check`。这份文档里出现任何统计值，都要能指回一条命令。
