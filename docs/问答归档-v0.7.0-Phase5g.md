## Q1: 教程爬取的页面的 UI 是白色的，不是统一整体的黑色，如何修复让 UI 配色与整体风格一致？

### 问题描述
- 教程页面 (`TutorialPage.css`) 硬编码了白色背景：`#ffffff` / `#fafafa` / `#f0f0f0`
- 暗黑模式下不跟随主题切换，导致视觉割裂
- 与项目其他页面（ServerList / ChatPanel）的暗黑风格不一致

### 解决方案
**核心原则**：所有 UI 颜色必须走 CSS 变量（`var(--color-*)`），禁止硬编码。

```css
/* 修复前（错误） */
.tutorial-page { background: #ffffff; }
.tutorial-card { background: #ffffff; }
.tutorial-sidebar { background: #fafafa; }

/* 修复后（正确） */
.tutorial-page { background: var(--color-bg-primary); }
.tutorial-card { background: var(--color-bg-card); }
.tutorial-sidebar { background: var(--color-bg-card); }
.tutorial-item { border: 1px solid var(--color-border); }
.tutorial-text { color: var(--color-text-primary); }
```

### 验证结果
Playwright 测试：`.tutorial-page` 在暗黑模式下 `backgroundColor = rgb(29, 29, 31)` ✓

### 关键经验
- **UI 暗黑统一硬约束**：所有新页面/组件 CSS 必须用 `var(--color-*)`，禁止硬编码
- 颜色映射表（亮色 → 暗色）：
  - `#ffffff` → `var(--color-bg-card)`
  - `#fafafa` → `var(--color-bg-primary)`
  - `#f0f0f0` → `var(--color-border)`
  - `#1d1d1f` → `var(--color-text-primary)`
  - `#86868b` → `var(--color-text-secondary)`

## Q2: AI 对话界面的发送箭头对齐有问题，如何参考主流开源 AI 对话界面修复？

### 问题描述
- 发送按钮使用 `SendOutlined`（纸飞机）图标，与主流 ChatGPT/Claude 风格不符
- 按钮为矩形（非圆形），输入框多行时按钮默认居中而非底部对齐
- 整体视觉不协调

### 调研结果（2026 主流 AI 对话界面）

| 平台 | 发送按钮 | 对齐 | 备注 |
|------|----------|------|------|
| **ChatGPT** | 蓝色圆形 + 向上箭头 | 底部对齐 | 单行圆角胶囊 |

**采用方案**：Claude 风格 + LobeChat 暗色 = 36×36 圆形 + ArrowUpOutlined

**图标替换**：
```typescript

// 修复后
```

### 验证结果
Playwright 测试：发送按钮 36×36 圆角 50% ArrowUpOutlined 对齐误差 0.000023px ✓

### 关键经验
- **AI 发送按钮对齐三件套**：`align-items: flex-end` + `align-self: flex-end` + `margin-bottom: 0`

## Q3: 教程页面选择抓取源一直不显示还报错，如何修复？

### 问题描述
- 打开"教程爬取" Modal 时，爬虫源列表始终为空
- 控制台报错（具体错误信息未显示）
- 用户无法选择爬虫源

### 根因分析
1. **主进程**：`tutorial:listSources` IPC handler 缺少错误处理，错误直接抛出未记录
2. **渲染进程**：未显示加载状态，UI 无任何反馈
3. **空源处理**：爬虫源为空时缺少友好提示

### 解决方案

**主进程修复**（`src/main/ipc/tutorial.ts`）：
```typescript
ipcMain.handle('tutorial:listSources', () => {
  try {
    const list = crawlerService.listSources()
    logger.info('TUTORIAL', `listSources 返回 ${list.length} 个源`)
    return list
  } catch (err) {
    logger.error('TUTORIAL', 'listSources 失败', { err: (err as Error).message })
    throw new Error(`列出爬虫源失败: ${(err as Error).message}`)
  }
})
```

**渲染进程修复**（`TutorialPage.tsx`）：
```typescript
const [sourcesLoading, setSourcesLoading] = useState(false)

const loadSources = useCallback(async () => {
  if (!isElectronAPIAvailable()) {
    message.error('electronAPI 不可用，无法加载爬虫源')
    return
  }
  setSourcesLoading(true)
  try {
    const list = await window.electronAPI.tutorialListSources()
    setSources(list)
    setSelectedSourceIds(list.filter((s) => s.enabledByDefault).map((s) => s.id))
  } catch (err) {
    const msg = err instanceof Error ? err.message : String(err)
    console.error('[Tutorial] 加载源列表失败:', err)
    message.error(`加载源列表失败: ${msg}`)
  } finally {
    setSourcesLoading(false)
  }
}, [])
```

### 验证结果
Playwright 测试：爬虫源 Modal 加载到 14 个源 ✓

### 关键经验
- **IPC handler 必须有 try-catch + 日志**：方便测试和事后分析
- **UI 状态三件套**：loading 状态 + 错误提示 + 空状态引导
- **测试可观测性**：通过日志系统可追溯到具体失败原因

## Q4: 服务器配置信息没有保存，如何修复持久化？

### 问题描述
- 添加服务器后，关闭应用再打开，配置丢失
- localStorage 可能在某些场景被清空（用户清缓存、profile 损坏）
- 缺少主进程层面的兜底持久化

### 解决方案：双重持久化策略

**架构**：
```
UI 变更
  ├─→ zustand state (内存) ← React 订阅立即生效
  ├─→ zustand persist (localStorage 缓存) ← 防 IPC 频繁往返
  └─→ IPC server:save (主进程 electron-store) ← 权威持久化
```

**实现**（`server-store.ts`）：
```typescript
/** 同步到主进程 */
async function syncToMain(servers: Server[]): Promise<boolean> {
  if (!isElectronAPIAvailable()) return false
  try {
    await window.electronAPI.serverSave(servers)
    return true
  } catch (err) {
    console.error('[ServerStore] 同步到主进程失败:', err)
    return false
  }
}

addServer: async (server) => {
  const newServers = [...get().servers, server]
  set({ servers: newServers })
  // 异步同步到主进程（不阻塞 UI）
  const ok = await syncToMain(newServers)
  if (!ok && isElectronAPIAvailable()) {
    console.warn(`[ServerStore] 服务器「${server.name}」未持久化到主进程`)
  }
},

/** 启动时从主进程加载（决策树） */
hydrateFromMain: async () => {
  if (!isElectronAPIAvailable() || get()._hydrated) return
  try {
    const mainServers = await window.electronAPI.serverList()
    const localServers = get().servers
    if (localServers.length === 0 && mainServers.length > 0) {
      // 决策1：localStorage 空 + 主进程有 → 用主进程
      set({ servers: mainServers, _hydrated: true })
    } else if (localServers.length > 0) {
      // 决策2：localStorage 有 → 以它为准，回写主进程
      set({ _hydrated: true })
      await syncToMain(localServers)
    } else {
      // 决策3：都没有
      set({ _hydrated: true })
    }
  } catch (err) {
    console.error('[ServerStore] 从主进程加载失败:', err)
    set({ _hydrated: true })
  }
},
```

**凭据安全**（localStorage 脱敏）：
```typescript
partialize: (state) => ({
  servers: state.servers.map((s) => {
    const { password, privateKey, passphrase, ...rest } = s
    return rest  // 脱敏：不写 localStorage
  }),
}),
```

### 验证结果
Playwright 测试：服务器配置写入主进程 + 回读成功，密码已加密 ✓

### 关键经验
- **双重持久化决策树**：localStorage 优先（响应快） + 主进程兜底（防丢失） + 启动回写（保一致）
- **localStorage 脱敏**：服务器密码/私钥/口令不写 localStorage，主进程用 safeStorage 加密
- **异步同步**：UI 变更不阻塞，失败有警告日志

## Q5: 如何建立一个后端日志系统模块，让测试可以直接读取日志文件以高效精准修改问题？

### 设计目标
1. **结构化**：JSON Lines，测试可机器解析
2. **可观测**：测试不需解析文本，直接读取结构化数据
3. **跨进程**：main + renderer 统一追踪（通过 correlationId）
4. **可测试**：通过 IPC 毫秒级读取，无需读文件
5. **可维护**：按天切分、大小轮转、自动清理

### 架构

```
┌─────────────────────────────────────────────────────────────┐
│  渲染进程 (React)                                            │
│  logger.info('UI', '按钮点击') ──IPC log:renderer──┐        │
└─────────────────────────────────────────────────────┼────────┘
                                                     │
                                                     ▼
┌─────────────────────────────────────────────────────────────┐
│  主进程 (Electron)                                          │
│  Logger (单例)                                              │
│  ├─ console 输出 (带 ANSI 颜色)                              │
│  ├─ 内存 buffer (1000 条 FIFO)                              │
│  └─ 文件落盘 (logs/app-YYYY-MM-DD.log + .1.log 滚动)        │
│                                                             │
│  IPC Handlers:                                              │
│  ├─ log:read       — 条件过滤读取                            │
│  ├─ log:stats      — 统计信息                                │
│  ├─ log:flush      — 异步刷新                                │
│  ├─ log:clearBuffer — 清空内存                                │
│  ├─ log:setMinLevel — 动态调整级别                            │
│  └─ log:renderer   — 渲染进程上报入口                        │
└─────────────────────────────────────────────────────────────┘
```

### 日志结构

```typescript
interface LogEntry {
  ts: string                    // ISO 8601 时间戳
  level: 'DEBUG' | 'INFO' | 'WARN' | 'ERROR' | 'FATAL'
  category: string              // 业务分类（IPC/SSH/LLM/CRAWLER/UI...）
  message: string               // 人类可读
  meta?: Record<string, unknown>  // 结构化数据
  correlationId?: string        // 跨调用追踪
  source: 'main' | 'renderer'  // 进程标识
  date: string                  // YYYY-MM-DD（按天切分用）
}
```

### 主进程 Logger（`src/main/services/log/logger.ts`）

```typescript
log(level, category, message, metaOrEntry?) {
  // 兼容两种调用方式：
  // 1. log(level, cat, msg, meta)
  // 2. log(level, cat, msg, { meta, correlationId, source })
  const isObjectArg = metaOrEntry && typeof metaOrEntry === 'object' && (
    'meta' in metaOrEntry || 'correlationId' in metaOrEntry || 'source' in metaOrEntry
  )
  const meta = isObjectArg ? metaOrEntry.meta : metaOrEntry
  const correlationId = isObjectArg ? metaOrEntry.correlationId : undefined
  const source = isObjectArg ? (metaOrEntry.source ?? 'main') : 'main'

  const entry: LogEntry = {
    ts: new Date().toISOString(),
    level, category, message, meta, correlationId, source,
    date: this.todayLocal(),
  }
  this.appendToBuffer(entry)  // 内存 buffer（测试用）
  this.writeToFile(entry)     // 文件落盘（事后分析）
  this.writeToConsole(entry)  // 控制台（开发实时看）
}
```

### IPC Handler（`src/main/ipc/log.ts`）

```typescript
/** log:renderer — 接收渲染进程日志 */
ipcMain.handle('log:renderer', (_event, payload) => {
  const validLevels: LogLevel[] = ['DEBUG', 'INFO', 'WARN', 'ERROR', 'FATAL']
  const level: LogLevel = validLevels.includes(payload?.level) ? payload.level : 'INFO'
  logger.log(level, payload?.category ?? 'RENDERER', payload?.message ?? '', {
    meta: { ...(payload?.meta ?? {}), _from: 'renderer' },
    correlationId: payload?.correlationId,
    source: 'renderer',
  })
  return true
})

/** log:read — 测试读取结构化日志 */
ipcMain.handle('log:read', (_event, filter) => {
  return logger.read(filter)  // 支持 level/category/keyword 过滤
})

/** log:stats — 测试验证 */
ipcMain.handle('log:stats', () => {
  return logger.stats()  // { total, byLevel, byCategory, bufferSize }
})
```

### 渲染端 Logger（`src/renderer/src/utils/logger.ts`）

行为：
