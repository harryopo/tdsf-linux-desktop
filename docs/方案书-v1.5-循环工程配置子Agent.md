## 2. 架构设计

### 2.1 三层架构

```
[AIPanel 演示模式 chip]
       ↓ loop:start IPC（problem + connId）
[LoopEngineeringSubagent] ← 继承 BaseSubagent
       ├── 1. Supervisor.chat → LLM 推理 → {hypothesis, fixCommand, confidence}
       ├── 2. AgentWorkflow.start({ getLlmFixCommand, sshExecutor, evidenceCollector })
       │      └── 7 步 HITL：collect→analyze→reason→check→confirm→execute→verify
       ├── 3. EventEmitter → IPC 推送 loop:step/decision/done/error
       └── 4. DiagnosticsService.ingestLog({source:'agent', level, raw})
```

### 2.2 与现有 Supervisor.chat 主路径的关系
- Supervisor.chat 仍是 AIPanel 普通对话的主路径（保留不动）
- 本子 agent 是"演示模式"专用编排器，复用 Supervisor.chat 做 LLM 推理
- 复用 AgentWorkflow 做 7 步 HITL 执行
- 复用 DiagnosticsService 做日志检测

### 2.3 IPC 通道设计

| 通道 | 方向 | 用途 |
|------|------|------|
| `loop:start` | invoke | 启动循环工程（参数：problem, connId, providerId?, strength?） |
| `loop:confirm` | invoke | 用户确认/拒绝（参数：correlationId, approved） |
| `loop:cancel` | invoke | 取消工作流（参数：correlationId） |
| `loop:llm-start` | push | LLM 推理开始 |
| `loop:llm-done` | push | LLM 推理完成（含 hypothesis） |
| `loop:step` | push | 工作流步骤变化（含完整 AgentWorkflowState） |
| `loop:decision` | push | 决策卡片就绪（含 DecisionCard） |
| `loop:done` | push | 工作流完成 |
| `loop:error` | push | 工作流出错 |

## 4. 关键技术决策

### 4.1 编排者模式（非标准 SubagentName）
LoopEngineeringSubagent 继承 BaseSubagent 但**不注册到 SubagentName 联合类型**（避免修改现有接口）。通过 `createLoopEngineeringSubagent()` 工厂方法创建，由 IPC 层直接持有实例。

### 4.2 EventEmitter 解耦
Subagent 内部 EventEmitter → IPC 层订阅 → safeSend 推送到渲染进程。这样 Subagent 不依赖 BrowserWindow，便于单元测试。

### 4.3 异步工作流 + 即时返回
`doExecute()` 不等待 7 步 HITL 完成，立即返回 `status: 'workflow-started'`。工作流完成后通过 `loop:done` 事件通知 IPC 层。这样 AIPanel 不会被阻塞。

### 4.4 LLM 推理结果注入
Supervisor.chat 推理得到的 `{hypothesis, fixCommand, confidence}` 通过 `evidenceCollector.llmAnalysis` 注入 AgentWorkflow，作为 `getLlmFixCommand` 的返回值。这样 7 步 HITL 工作流可以直接使用 LLM 推理结果。

### 4.5 日志转发到 DiagnosticsService
在 LLM 推理、工作流步骤变化、用户确认、错误等关键节点转发日志到 DiagnosticsService.ingestLog()。实现"建立一个检测的后端，当循环工程启动时利用后端的日志进行分析"。

### 4.6 演示模式 UI 切换
在 AIPanel 新增"演示模式"chip：
- 切换到演示模式时，输入框发送消息调用 `loop.start(text, connId)` 而非 `send(text)`
- 消息区域渲染 `<LoopWorkflowPanel loop={loop} />` 而非 `LiveMessageRow`
- 标题栏徽章显示"循环工程运行中" / "演示就绪"
- 无活跃 SSH 连接时显示"未连接"警告徽章

## 6. 风险与限制

### 6.1 已知限制
- LLM 推理依赖真实 Provider 配置（API Key）
- SSH 执行依赖真实 SSH 连接
- 当前未实现 SSH 执行结果的回显到 UI（只在日志中可见）
- 当前未实现"在终端运行"按钮的真实接线（仍为 mock）

### 6.2 后续优化方向
1. **SSH 执行结果回显**：在 DecisionCardView 中显示执行后的 stdout/stderr
2. **"在终端运行"按钮接线**：把 LoopWorkflowPanel 的 SSH 命令注入到终端
3. **演示模式历史记录**：把完成的循环工程记录到 history 页面
4. **失败重试**：verify 步骤失败后，提供"重新推理"按钮
5. **多轮对话**：演示模式支持追问，把上一轮结果作为下一轮的上下文
