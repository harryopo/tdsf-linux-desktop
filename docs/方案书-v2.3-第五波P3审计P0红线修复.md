## 2. P0 问题清单（9 个，按优先级排序）

### 2.1 安全类 P0（最高优先级，4 个）

#### P0-S1: ssh:exec 无白名单/审计/HITL（问题 #41）
- **文件**：`src/main/ipc/ssh.ts:170-177`
- **风险**：SSH 命令直接透传，无 zod 校验 + 无审计日志 + 无 R12 三态权限审批
- **修复方案**：
  1. 添加 zod schema 校验 `command` 非空字符串
  2. 添加命令审计日志 `logger.info('SSH_EXEC', { sessionId, command: redactSecrets(command) })`
  3. 接入 R12 三态权限审批（危险命令如 `rm -rf` 走 ALWAYS 审批）
- **工作量**：4 小时

#### P0-S2: dangerouslySetInnerHTML 无 XSS 防护（问题 #43）
- **文件**：`src/renderer/src/components/tutorial/TutorialPage.tsx:650`
- **风险**：`renderMarkdown(detail.content)` 输出 HTML 直接注入 DOM，爬虫抓取的 HTML 可能包含恶意 `<script>` / `<iframe>`
- **修复方案**：
  1. 引入 `DOMPurify` 库（npm: dompurify, 28KB gzip）
  2. `dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(renderMarkdown(detail.content)) }}`
  3. 或改用 `react-markdown` + `rehype-raw` + `rehype-sanitize`
- **工作量**：2 小时

#### P0-S3: ssh.ts 5 处 console.error 未脱敏（问题 #33）
- **文件**：`src/main/ipc/ssh.ts`（line 154, 457, 555, 646, 735）
- **风险**：违反 A3 红线，SSH 错误信息可能包含主机名/用户名/路径，未脱敏直接输出
- **修复方案**：
  1. 在 ssh.ts 头部添加 `import { logger } from '../services/log/logger'`
  2. 5 处 `console.error` 改为 `logger.error('SSH', '操作失败', { error: redactSecrets((err as Error).message) })`
  3. 导入 `redactSecrets` from `../services/security/redact`（或合并后的统一函数）
- **工作量**：1 小时

#### P0-S4: 两套脱敏函数 DRY 违规（问题 #36）
- **文件 1**：`src/main/services/security/redact.ts` 定义 `redactSensitiveInfo`
- **文件 2**：`src/main/core/agent/providers/redact.ts` 定义 `redactSecrets`
- **风险**：两套脱敏函数实现可能存在规则覆盖不一致
- **修复方案**：
  1. 对比两套函数的脱敏规则覆盖范围
  2. 保留覆盖更全的 `redactSecrets`（已在 Agent 链路使用）
  3. 将 `redactSensitiveInfo` 标记为 deprecated，迁移 `daily-decision-archive.ts` 改用 `redactSecrets`
  4. 或将两者合并为一个函数，保留双名导出做兼容
- **工作量**：2 小时

### 2.2 红线类 P0（高优先级，4 个）

#### P0-R1: ssh:exec 字面量违反 B4（问题 #16）
- **文件**：`src/main/ipc/ssh.ts:170`
- **风险**：未使用 `SSH.EXEC` 常量，违反 IPC 4 步同步铁律
- **修复方案**：
  1. 在 `src/shared/ipc-channels.ts` 的 SSH 常量中新增 `EXEC: 'ssh:exec'`
  2. ssh.ts:170 改为 `ipcMain.handle(SSH.EXEC, ...)`
  3. preload 对应位置改为引用 `SSH.EXEC` 常量
  4. electron.d.ts 类型声明同步
- **工作量**：30 分钟

#### P0-R2: preload 164 处字面量违反 B4（问题 #17）
- **文件**：`src/preload/index.ts`
- **风险**：164 处 `ipcRenderer.invoke('字面量')` 直接使用字符串，未引用 `@shared/ipc-channels` 常量
- **修复方案**：
  1. 在 `src/shared/ipc-channels.ts` 补齐所有域的常量定义
  2. 将 preload 164 处字面量替换为常量引用
  3. 同步更新 electron.d.ts
- **工作量**：8 小时

#### P0-R3: main.tsx 28 处硬编码颜色违反 B2（问题 #57）
- **文件**：`src/renderer/src/main.tsx`（line 45-95）
- **风险**：Antd ConfigProvider 28 处硬编码颜色（暗色 14 + 亮色 14），违反 B2 `var(--color-*)` 约束
- **修复方案**：
  1. 在 `trae-tokens.css` 中定义 Antd 桥接 token：`--trae-antd-primary: #387BFF` 等
  2. main.tsx 改为 `colorPrimary: 'var(--trae-antd-primary)'`
  3. 确保 Antd ConfigProvider 支持 CSS 变量（Antd 5.20+ 支持）
- **工作量**：3 小时

#### P0-R4: main/index.ts 5 处 console 违反 logger 规范（问题 #34）
- **文件**：`src/main/index.ts`（line 47, 69, 75, 77, 89）
- **风险**：应用启动阶段直接 console 输出，绕过 logger 结构化日志
- **修复方案**：替换为 `logger.info('IPC', ...)` / `logger.warn('TUTORIAL', ...)` / `logger.error('MCP', ...)`
- **工作量**：30 分钟

### 2.3 维护类 P0（中优先级，1 个）

#### P0-M1: AIPanel.tsx 1667 行违反 B1（问题 #1）
- **文件**：`src/renderer/src/components/workbench/AIPanel.tsx`
- **风险**：单文件超 B1 限制 3.3 倍，含 Composer / MessageList / TokenBudget / ToolPanel 多个子组件待拆分
- **修复方案**：按注释计划拆分为 4 个独立组件
  1. `Composer.tsx`（输入框 + 工具栏 + 发送按钮）
  2. `MessageList.tsx`（消息列表 + 滚动 + 加载更多）
  3. `TokenBudget.tsx`（token 预算展示 + 进度条）
  4. `ToolPanel.tsx`（工具调用面板）
- **工作量**：8 小时
