## Q1：LDP 抓取任务为何只跑到 3/313 就退出？

**现象**：
- 启动 `crawlLdpHowtos` 后只输出 3 条进度，随后进程以 exit code 0 退出
- 没有错误堆栈，err.log 为空
- 期望抓取 313 个 HOWTO，实际只完成 3 个

**根因分析**：
1. `crawlLdpHowtos` 用 `Promise.all(links.map(async (url) => ...))` 启动 313 个并发任务
2. Token Bucket 限流 3 并发 + 1 req/s，前 3 个 fetch 在等响应
3. electron 主进程检测到「没有立即需要的任务」，在 setTimeout 之前就退出
4. 这是 Windows + ELECTRON_RUN_AS_NODE 模式下的**事件循环时序问题**：
   - `setTimeout(abort, 90_000)` 注册了宏任务
   - 但 `Promise.all` 的子 promise 还在 pending 状态时，主进程认为「没事可做」直接退出
   - 实际所有 fetch 都被中途丢弃

**修复方案**：
不用 `crawlLdpHowtos`（其并发模型不稳定），改写为 `verify-ldp-small.ts`：
- 先 `politeFetch` 抓索引页 → 解析 313 个 URL
- 再用 `for` 循环顺序 `await politeFetch` 抓前 30 条
- 30 条 × 1 req/s = 30 秒，但每个 await 阻塞主循环，进程无法提前退出

**验证结果**：
- 30 条抓取，29 成功入库，1 失败（`Adv-Bash-Scr-HOWTO/index.html` 是 multi-page 文档）
- 54.8s 完成，时序稳定

**适用范围**：
- 任何「大量 HTTP 请求 + 并发」场景
- Windows + Electron 环境优先用顺序 await
- Linux/macOS 可能不会触发此问题

## Q2：upsertMany 为何触发 `NOT NULL constraint failed: knowledge_entries.problem`？

**现象**：
- LDP 抓取 29 条成功，准备入库
- 事务失败：`NOT NULL constraint failed: knowledge_entries.problem`
- 所有 29 条都没入库

**根因**：
- `upsertMany` 的 SQL 期望 `@problem` 字段非空
- 在 `tutorial-repo.ts:54-89` 的 `toKnowledgeEntry()` 里，`problem: t.summary` 来自 `parseHtmlToTutorial()` 提取的 HTML summary
- LDP 部分页面（如 `Access-HOWTO`）HTML 结构特殊，没有标准 `<meta description>` 或首段
- `parseHtmlToTutorial` 内部如果找不到 summary，可能返回 `""` 空串
- 空串在 SQLite NOT NULL 约束下被拒绝

**第一次错误尝试**：
我手工 map TutorialEntry[] → KnowledgeEntry[]，传 `problem: t.summary`，但这**绕过**了 `toKnowledgeEntry` 的内部逻辑：
- `toKnowledgeEntry` 还会处理标签组合、JSON 序列化、successRate 计算
- 手工 map 出来的对象没有这些字段，触发约束失败

**正确修复**：
- **直接传 `repo.upsertMany(entries)`**，让 `toKnowledgeEntry` 统一处理
- entries 必须是 `TutorialEntry[]`（不是 KnowledgeEntry[]）

**修复后结果**：
- inserted=29, updated=0, skipped=0
- 全部 29 条成功入库

**经验教训**：
- 不熟悉的仓储层，**优先传业务模型（TutorialEntry）让适配器（toKnowledgeEntry）处理**
- 手工 map 业务模型 → 存储模型是高风险操作，容易漏字段或约束

## Q3：LDP 索引页的相对路径如何正确解析？

**现象**：
- 旧代码 `${LDP_BASE_URL}/${href.replace(/^\//, '')}` 拼接出错
- 链接 `../HOWTO/HTML/xxx.html` 拼成 `https://www.tldp.org/../HOWTO/HTML/xxx.html`
- 404 错误

**根因**：
- LDP 索引页（`https://www.tldp.org/HOWTO/HOWTO-INDEX/howtos.html`）里所有 HOWTO 链接都是**相对路径** `../HOWTO/HTML/xxx.html`
- 字符串拼接无法处理 `../` 路径回退

**修复方案**（[`ldp-howtos-offline.ts:37-78`](file:///d:/ai/linux教学一体/tdsf-linux-desktop/src/main/services/tutorial/crawler/ldp-howtos-offline.ts#L37-L78)）：
```typescript
// 1. 区分绝对/相对/协议相对路径
if (href.startsWith('http://') || href.startsWith('https://')) {
  fullUrl = href
} else if (href.startsWith('//')) {
  fullUrl = 'https:' + href
} else if (href.startsWith('/')) {
  fullUrl = `https://www.tldp.org${href}`
} else {
  // 相对路径：用 URL 解析
  try {
    fullUrl = new URL(href, LDP_HOWTO_INDEX).toString()
  } catch {
    const cleaned = href.replace(/^\.\.\//, '').replace(/^\.\//, '')
    fullUrl = `${LDP_BASE_URL}/${cleaned}`
  }
}
// 2. 规整化：去掉路径中的 ../
try {
  const u = new URL(fullUrl)
  u.pathname = u.pathname.replace(/\/\.\.\//g, '/').replace(/^\.\.\//, '')
  fullUrl = u.toString()
} catch { /* ignore */ }
```

**关键点**：
- `new URL(href, baseUrl)` 是 WHATWG URL 标准，自动处理 `../`
- 规整化 `u.pathname = u.pathname.replace(/\/\.\.\//g, '/')` 进一步清理
- 兜底逻辑（catch）保留

| 层 | 代码位置 | 职责 |
|---|---|---|
| **证据层（Evidence）** | `src/main/services/tutorial/crawler/*-offline.ts` | 4 大权威源（tldr/linux-command/LDP/AoC）+ politeFetch 合规 |

| **记忆层（Memory）** | `src/main/services/db/knowledge-repo.ts` + `tutorial-repo.ts` | 统一 schema `knowledge_entries`（type=tutorial/command_skill/incident_case）+ TutorialEntry↔KnowledgeEntry 映射 |
| **风险层（Risk）** | `polite-fetch.ts` + source metadata | UA 标识 + 1 req/s + 429 Retry-After + License 红线 + 国内镜像 |
| **可视化层（Visualization）** | `src/renderer/src/pages/TutorialPage.tsx` + `TutorialDetailPage.tsx` | 自动加载真实数据 + 数据源标签 + mock 兜底 + Markdown 章节解析 |

**5 层对齐的价值**：
- **可替换**：每层独立，可以替换证据源（如加 ms-learn、kernel-org）不影响其他层
- **可观测**：每一层都打日志 + 进度回调，失败可定位
- **可解释**：可信度算法展示 6 源证据权重，运维知识库展示 4 源数据来源
