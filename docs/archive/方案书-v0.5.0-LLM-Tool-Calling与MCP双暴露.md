## 1. 一句话目标

让 LLM 能调用 5 个真实工具（SSH/教程/部署/架构感知/监控），
并把同一组能力以 MCP Server 形式暴露给外部 Claude Code，
闭合 **"AI 整体助手"** 的核心链路。

## 3. 功能范围

### 3.1 5 个 Tool Calling 工具

| 工具名 | 能力 | 输入参数 | 返回 | 风险等级 |
|--------|------|---------|------|---------|
| `ssh_exec` | 在指定 session 上执行一条命令 | `sessionId`, `command`, `timeoutMs?` | `{ stdout, stderr, exitCode }` | **高**（任意命令） |
| `tutorial_search` | 关键词搜教程知识库 | `query`, `category?`, `distro?`, `limit?` | `TutorialEntry[]` | 低 |
| `deploy_list_templates` | 列出可用的部署模板 | `category?` | `DeployTemplate[]` | 低 |
| `profiler_run` | 跑 27 项并发探查 | `sessionId`, `host` | `ProfilerRunResponse` | 中（高并发 IO） |
| `monitor_get_data` | 拉取最新一次监控数据 | `sessionId` | `MonitorData` | 低 |

### 3.2 MCP Server 暴露

- 新增 `src/main/services/mcp/server.ts`（沿用现有 mcp 服务目录）
- 注册 5 个 MCP 工具（同上名称 + 描述），通过 stdio 与外部 Claude Code 通信
- 启动方式：CLI 子命令 `tdsf-mcp` 或环境变量 `TDSF_MCP_MODE=1`
- 安全：MCP 调用需先建立 SSH session（与 LLM Tool Calling 共享 session pool）

### 3.3 渲染端 UI 增强

- ChatPanel 新增"工具调用"折叠面板，实时展示 LLM 调了哪些工具、参数、结果
- 支持 **人机协同审批**：high 风险工具（ssh_exec）执行前弹出确认对话框
- 工具调用历史持久化到 SQLite（便于复盘）

## 4. 非功能要求

| 维度 | 指标 | 备注 |
|------|------|------|
| 响应延迟 | 工具调用 P95 < 3s（含网络） | LLM 决策时间不计 |
| 并发安全 | 同一 session 串行执行不同命令 | 用 session-level mutex |
| 错误处理 | 工具失败必须返回结构化错误（含 errorCode + message） | LLM 能基于错误自纠 |
| 安全 | high 风险工具必须人工确认 | 不可跳过 |
| 审计 | 所有工具调用记录到 `decision_history` 表 | 包含时间/参数/结果/用户 |
| 测试 | 单测覆盖率 ≥ 85% | 5 工具每个至少 3 个用例 |
| 文档 | 每个工具的 OpenAPI 描述自动生成 MCP schema | 单一来源 |

## 5. 技术选型

### 5.1 Tool Calling 框架

| 方案 | 优点 | 缺点 | 推荐 |
|------|------|------|------|
| Vercel AI SDK 现有 `generateText({ tools })` | 项目已有 `ai@4.0.0`，零新增依赖 | 工具 schema 需手写 | ✅ 推荐 |
| LangChain.js `DynamicStructuredTool` | 生态丰富，文档多 | 新增 5+ 依赖，与 Vercel AI 冲突 | ❌ |
| 手写 OpenAI Function Calling | 最小依赖 | 重复造轮子，与流式推送耦合难 | ❌ |

**结论**：用现有 Vercel AI SDK 的 `tool()` + `generateText()` API。

### 5.2 MCP SDK

- 已在依赖：`@modelcontextprotocol/sdk@1.0.4`
- 沿用现有 `src/main/services/mcp/server.ts` 框架
- 推荐调用 `mcp-builder` skill 生成 schema 模板

### 5.3 数据流

```
ChatPanel (renderer)
  ↓ window.electronAPI.llmChatWithTools
preload bridge
  ↓ ipcMain.handle('llm:chat-with-tools')
LLM service (main)
  ↓ generateText({ model, tools, messages })
  ↓ tool.execute() → 调 sshManager / tutorialRepo / deployService / profiler / monitor
  ↓ tool result → LLM 继续推理
  ↓ 最终文本 → 返回 renderer
```

### 5.4 人机协同审批

```
LLM 决策要调 ssh_exec
  ↓
检测到 high 风险
  ↓
推 IPC 事件 'llm:tool-confirm-request' 到 renderer
  ↓
Modal 弹窗显示：命令内容 + 风险等级 + 预计影响
  ↓
用户点 "批准" / "拒绝"
  ↓
继续执行 / 中止
```

## 8. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| LLM 误调危险命令（rm -rf /） | 🔴 高 | 二次确认 + 命令黑名单 + 风险评估 |
| 工具调用超时导致 session 卡死 | 🟡 中 | 5s/15s/60s 三档 timeout + 强制 kill |
| MCP Server 暴露过宽攻击面 | 🟡 中 | 仅 stdio 模式（不开放网络端口）+ 命令白名单 |
| LLM 死循环调工具 | 🟡 中 | maxIterations=5 硬限制 + 累计 token 告警 |
| 工具 schema 与实际能力漂移 | 🟢 低 | 自动从 zod schema 生成 TypeScript + MCP schema |

## 附录 B：MCP 工具注册示例

```typescript
// mcp/tools/ssh-exec.ts
server.tool(
  'ssh_exec',
  '在指定 SSH session 上执行一条命令',
  {
    sessionId: z.string(),
    command: z.string(),
    timeoutMs: z.number().optional(),
  },
  async ({ sessionId, command, timeoutMs }) => {
    // 复用 LLM tool 的 execute 逻辑
    return await sshExecTool.execute({ sessionId, command, timeoutMs })
  }
)
```
