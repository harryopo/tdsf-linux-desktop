## 2. 词库导入器架构

### 2.1 三个 Node 脚本（独立、可重跑）

```
scripts/dict-import/
├── jaywcjlove.mjs    # 解析 jaywcjlove 仓库 → .cache/jaywcjlove.json
├── tldr.mjs          # 解析 tldr 仓库     → .cache/tldr-zh.json
├── merge.mjs         # 合并三源 + 写主词库 → src/renderer/.../linux-commands-zh.json
└── .cache/           # 中间产物（gitignore）
    ├── jaywcjlove.json
    └── tldr-zh.json
```

**设计原则**：
- **不修改开源仓库本身**（仅 read-only 解析）
- **中间产物可重跑**（删 .cache 重跑三个脚本即可重建）
- **容错优先**（单条失败不中断整体）

### 2.2 jaywcjlove.mjs 关键算法

```javascript
// 1. 读 dist/data.json（67KB 全量索引，617 条命令）
// 2. 遍历 commandNames，尝试加载 command/{name}.md
// 3. 从 .md 提取：
//    - 描述（第 3 行非空行）
//    - 语法（### 语法 段）
//    - 选项（## 选项 段，每行 "-X, --yy: 描述"）
//    - 实例（### 实例 段的第一个代码块）
//    - 补充说明（## 补充说明 段）
// 4. 输出 .cache/jaywcjlove.json
```

**关键正则**（处理 CRLF + 中英冒号）：

```javascript
// 选项提取：-X, --yy: 描述  或 -X：描述
const m2 = cleanLine.match(
  /^(-{1,2}[a-zA-Z0-9][a-zA-Z0-9_-]*)(?:\s*,\s*--([a-zA-Z0-9_-]+))?\s*[:：]\s*(.+)$/
)
```

**统计**（实际运行）：
- data.json 总条数：617
- .md 命中：约 600（基本全量）
- 选项提取：~1500（多命令合计）
- 示例提取：~400

### 2.3 tldr.mjs 关键算法

```javascript
// 1. 扫描 pages.zh/common/*.md（1100+ 条）
// 2. 解析每个 .md：
//    - 标题：# 命令名
//    - 描述：> 开头的 1-2 行（跳过"更多信息"）
//    - 示例：- 描述 + `命令`（1-3 行间隔内）
// 3. 跨平台合并：同命令在 linux/common/osx/common 合并 example
// 4. 输出 .cache/tldr-zh.json
```

**示例提取的难点**：tldr 格式是 `- 描述\n  \`命令\``，但描述和命令之间可能跨多行（有空行）。

**解决方案**：描述行后 1-3 行内查找代码块，遇到空行 + 非代码行则停止。

### 2.4 merge.mjs 合并策略

```
Pass 1: v1.1.0 人工词条（最高优先级，字段全保留）
Pass 2: jaywcjlove 补充（不覆盖 v1.1.0，仅补 example / _options）
Pass 3: tldr-zh 补充（同上策略）
Pass 4: 写 .cache/jaywcjlove.json 中 _options 为独立词条（-l, --all, -R 等）
Pass 5: 输出最终 linux-commands-zh.json + 统计信息
```

**合并关键规则**：
- `command.category` 守卫：仅 `category='command'` 的词条视为命令
- `option.category` 守卫：仅 `category='option'` 的词条视为选项
- `error.category` 守卫：v1.1.0 人工标注的 25 条错误信息不被动
- `courseChapter` 字段：v1.1.0 课程关联不动，v1.2.0 新增 29 条

## 3. 词典数据结构（v1.2.0）

### 3.1 顶层 Schema

```typescript
interface Dict {
  version: string           // '1.2.0'
  updatedAt: string         // '2026-07-25'
  source: string            // 'jaywcjlove/linux-command(MIT) + tldr-pages(CC BY 4.0) + manual v1.1.0'
  stats: {
    totalEntries: number
    byCategory: Record<'command'|'option'|'error'|'term'|'phrase', number>
    bySource: Record<'jaywcjlove'|'tldr'|'manual', number>
    v11Base: number         // 继承自 v1.1.0 的条数
    addedFromJay: number    // jaywcjlove 新增
    addedFromTldr: number   // tldr 新增
    merged: number          // 跨源合并
    optionsAdded: number    // 选项独立词条数
  }
  entries: Record<string, DictEntry>
}

interface DictEntry {
  zh: string                 // 中文释义（必填）
  pos?: 'v.' | 'n.' | 'adj.' | 'adv.' | 'phr.'
  example?: string           // 用法示例
  category: 'command' | 'option' | 'error' | 'term' | 'phrase'
  level: 'basic' | 'intermediate' | 'advanced'
  courseChapter?: string     // 课程章节 ID（如 'ch05-permission'）
  _sources?: string[]        // 来源（['jaywcjlove'] / ['tldr'] / ['manual']）
  syntax?: string            // 命令语法
  detail?: string            // 补充说明
}
```

## 5. 关键决策与踩坑

### 5.1 仓库克隆完整性

**问题**：首次 `git clone` 只拉取了根目录元文件（README/LICENSE/.gitignore），子目录 `command/` 和 `pages.zh/` 缺失。

**解决**：
- 验证 `ls opensource-reference/linux-command/command` 应有 600+ .md
- 验证 `ls opensource-reference/tldr/pages.zh/common` 应有 1100+ .md
- 若缺失，重新 `git clone` 或 `git fetch && git checkout`

### 5.2 选项提取的正则坑

**问题 1**：jaywcjlove 的 .md 在 Windows 检出为 CRLF，`\r` 干扰正则。
- 解决：`cleanLine = line.replace(/\r$/, '').trim()`

**问题 2**：jaywcjlove 选项段有 `## 选项` 和 `### 选项` 两种标题层级。
- 解决：`sections = mdContent.split(/\n##+/)` 一并处理

**问题 3**：冒号有半角 `:` 和全角 `：` 两种。
- 解决：正则用 `[:：]` 字符类

### 5.3 tldr 跨平台合并

**问题**：tldr 的 `pages/common/ls.md`、`pages/linux/common/ls.md`、`pages/osx/common/ls.md` 三个文件描述同一命令。
- 解决：merge.mjs 用 `key = normalizeCmd(title)` 归一化，example 数组跨平台合并。

### 5.4 词典 JSON 编译可见性

**问题**：v1.1.0 时词典 JSON 加载失败，因为 `tsconfig.web.json` 默认不 include `.json`。
- 解决（v1.1.0 已修）：`"include": ["src/renderer/src/**/*", "src/renderer/src/**/*.json", ...]`

### 5.5 容量控制

**问题**：jaywcjlove 有些命令有 30+ 选项（如 `curl`），全部入库会膨胀。
- 解决：`extractOptions` 限制每命令最多 12 个选项。

## 9. 经验总结

### 9.1 词典扩充的正确姿势

> **不要从零手搓，永远先调研开源词库**。
> - 2-3 天手搓 200 词 vs 1 天集成 2200 词
> - 开源词库有社区维护，质量有保障
> - License 红线先核查（MIT/Apache 优先，AGPL/GPL 排除）

### 9.2 词库合并的"金字塔"策略

```
       [人工校对层]  ← 错误信息、课程关联（少量但关键）
      [开源词库层]  ← jaywcjlove + tldr（大批量但通用）
     [自动化层]    ← 导入器 + 合并器（无人值守）
```

**优先级**：人工 > 开源 > 自动化生成。冲突时人工胜出。

### 9.3 词条字段的最小公约数

不同源的字段差异巨大（jaywcjlove 有 `syntax` / `detail`，tldr 只有 `example`），合并时只取共同字段 + `_sources` 数组标记来源，方便后续质量追溯。

### 9.4 测试驱动词库质量

> 词库是数据，但数据也要测试。
> - 数量断言（>= 2000 词条）
> - 抽样断言（高频命令必须存在）
> - 类别分布（command 应占主导）
> - 来源透明度（_sources 字段）

这样保证词库质量不再依赖"肉眼检查"。
