## 3. 关键设计决策

### 3.1 决策 D1：离线包优先 vs 在线爬
**决策**：**离线包优先（Phase 1），在线增量补充（Phase 2）**

| 维度 | 离线包 | 在线爬 |
|---|---|---|
| 礼仪风险 | 零（官方主动提供） | 有（需守 Crawl-delay） |
| 速度 | 快（一次下载，多次解析） | 慢（受限于服务器响应） |
| 时效性 | 月度/季度 | 实时 |
| 适用 | 大量历史教程 | 增量更新 |

**正确做法**：先离线包把"骨"搭起来（100+ 篇），再用在线爬做"肉"（增量补新）。

### 3.2 决策 D2：Crawlee vs 自研
**决策**：**Crawlee（22K stars，2026 标准）**

- 自研：写并发控制 + 重试 + 限流 ≈ 500 行代码，且不专业
- Crawlee：开箱即用，内置 robots.txt 解析 + 限流 + 重试
- 项目已是 Node.js+TS，Crawlee 零学习成本
- 缺点：Crawlee 较重（依赖大），但可按需引入（`@crawlee/core` + `@crawlee/cheerio`）

### 3.3 决策 D3：HTML → Markdown 转换
**决策**：**turndown**（成熟库，5.5K stars）

- 备选：`html-to-md` / `@joplin/turndown` / `node-html-markdown`
- turndown 插件生态好（GFM、表格、代码块）
- 选 turndown + turndown-plugin-gfm

### 3.4 决策 D4：教程去重策略
**决策**：**URL hash 作为主键去重**

```typescript
// 主键 = sha256(source.url).slice(0, 16)
function makeTutorialId(url: string): string {
  return `tut-${createHash('sha256').update(url).digest('hex').slice(0, 16)}`
}
```

- 重复爬同一 URL → upsert（更新 content / crawledAt）
- 离线包解析 = 在线重爬（ID 稳定）

### 3.5 决策 D5：用户许可
**决策**：**首次使用前弹窗确认**

```typescript
// TutorialPage 顶部加 [教程来源说明] 折叠面板
// [刷新教程] 按钮首次点击前弹窗：
//   - 提示将访问哪些官方源
//   - 显示 robots.txt 摘录
//   - 用户勾选"我已了解并同意"后启用
```

- 符合 7.2 节"完成前不跑 verification-before-completion" → 留审计
- 不偷偷爬，给用户控制感

```typescript
// services/tutorial/crawler/arch-wiki-offline.ts
import { createWriteStream, createReadStream } from 'node:fs'
import { mkdir, rm } from 'node:fs/promises'
import { pipeline } from 'node:stream/promises'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { extract } from 'tar' // npm i tar
import * as cheerio from 'cheerio'
import TurndownService from 'turndown'
import { createHash } from 'node:crypto'

const ARCH_WIKI_DUMP_BASE = 'https://wiki.archlinux.org/static'
const LATEST_DUMP_URL = `${ARCH_WIKI_DUMP_BASE}/archwiki-latest.tar.gz`

export async function crawlArchWikiOffline(
  onProgress: (msg: string, pct: number) => void
): Promise<TutorialEntry[]> {
  onProgress('下载 Arch Wiki 月度快照...', 0)
  const tmpDir = join(tmpdir(), `archwiki-${Date.now()}`)
  await mkdir(tmpDir, { recursive: true })
  const tarPath = join(tmpDir, 'archwiki.tar.gz')
  
  // 下载（带进度）
  await downloadWithProgress(LATEST_DUMP_URL, tarPath, (p) => 
    onProgress(`下载中... ${(p * 100).toFixed(0)}%`, p * 0.4)
  )
  
  onProgress('解压中...', 0.4)
  const extractDir = join(tmpDir, 'extracted')
  await mkdir(extractDir, { recursive: true })
  await pipeline(
    createReadStream(tarPath),
    extract({ cwd: extractDir })
  )
  await rm(tarPath)
  
  // 解析所有 HTML
  onProgress('解析 HTML → Markdown...', 0.5)
  const entries: TutorialEntry[] = []
  const htmlFiles = await glob('**/*.html', { cwd: extractDir })
  
  const turndown = new TurndownService({ headingStyle: 'atx', codeBlockStyle: 'fenced' })
  turndown.use(turndownPluginGfm)
  
  for (let i = 0; i < htmlFiles.length; i++) {
    const file = htmlFiles[i]
    const html = await readFile(join(extractDir, file), 'utf-8')
    const entry = parseArchWikiHtml(html, file, turndown)
    if (entry) entries.push(entry)
    
    if (i % 50 === 0) {
      onProgress(`解析 ${i}/${htmlFiles.length}`, 0.5 + (i / htmlFiles.length) * 0.4)
    }
  }
  
  onProgress(`完成！共 ${entries.length} 篇`, 1.0)
  await rm(tmpDir, { recursive: true })
  return entries
}
```

```typescript
// services/tutorial/crawler/crawlee-adapter.ts
import { CheerioCrawler, Configuration } from 'crawlee'

const ROBOTS_RESPECT = {
  'help.ubuntu.com': 5_000,      // 5s
  'access.redhat.com': 10_000,   // 10s
  'wiki.debian.org': 20_000,     // 20s
  'learn.microsoft.com': 2_000,  // 2s 礼貌
  'www.digitalocean.com': 2_000, // 2s 礼貌
  'linuxize.com': 2_000,         // 2s 礼貌
  'www.tecmint.com': 2_000,      // 2s 礼貌
}

export async function crawlWithCrawlee(
  sourceId: string,
  baseUrl: string,
  urlFilter: (url: string) => boolean,
  parser: (html: string, url: string) => TutorialEntry | null,
  onProgress: (msg: string, pct: number) => void
): Promise<TutorialEntry[]> {
  const domain = new URL(baseUrl).hostname
  const delayMs = ROBOTS_RESPECT[domain] ?? 5_000
  
  const crawler = new CheerioCrawler({
    maxRequestsPerMinute: Math.floor(60_000 / delayMs),
    maxConcurrency: 1,  // 严格单线程保证不超 delay
    async requestHandler({ request, $ }) {
      const html = $.html()
      const entry = parser(html, request.url)
      if (entry) results.push(entry)
    },
    failedRequestHandler({ request }) {
      console.warn(`[Crawler] 失败: ${request.url}`)
    }
  })
  
  // 启动入口
  await crawler.run([baseUrl])
  return results
}
```

## 5. 风险与回退

| 风险 | 概率 | 影响 | 回退方案 |
|---|---|---|---|
| Arch Wiki dump 链接失效 | 低 | 中 | 改用 GitHub 源仓库克隆（archlinux/archwiki 180 stars） |
| Crawlee 引入后包体积增大 50MB+ | 中 | 中 | 改用 cheerio + 手写并发（10 行代码 vs 50MB 依赖） |
| HTML→MD 转换质量差 | 中 | 高 | 备选 joplin/turndown 插件链；最差情况人工校对 5 篇 |
| 在线爬被封 IP | 低 | 中 | 严格守 Crawl-delay + 增加重试；最差仅离线包可用 |
| 版权投诉 | 极低 | 高 | 严格只整理摘要 + 标注原文链接（已设计）+ 必要时 DMCA 响应 |

### 12.2 取消机制关键修复

在本地验证过程中发现：`polite-fetch` 在外部 `AbortSignal` 触发取消时，如果请求已经发出，会被误判为"请求超时 408"，而不是"用户取消 499"。

**修复位置**：`src/main/services/tutorial/crawler/polite-fetch.ts` catch `AbortError` 分支。

```typescript
// AbortError：区分外部取消与内部超时
if ((err as Error).name === 'AbortError') {
  // 外部信号取消优先判定为 499，避免被当成超时 408
  if (externalSignal?.aborted) {
    if (rateLimiter) rateLimiter.release()
    throw new PoliteFetchError('请求已取消', 499, url)
  }
  // ... 超时重试逻辑
}
```

该修复确保用户点击"取消抓取"后，正在进行的 HTTP 请求会立即以 499 状态退出，服务层正确识别为取消而非超时。
