- **main.tsx**（164 行）：`createRoot` + `ConfigProvider` 配置 Ant Design 主题（苹果极简 token），通过 `useThemeStore` 响应式切换亮/暗主题，同步 `<html data-theme>` 属性。

## 十、风险与建议

### 10.1 已知风险

1. **IPC 通道数爆炸**：v0.9.4 已 78 个，v0.9.5 补齐后 89+ 个，v1.0 重构后预计 100+ 个。需建立 IPC 命名规范（kebab-case + 命名空间前缀）+ 定期 review。
2. **Zustand store 缺失**：v0.9.5-pre 需新建 8 个 store 骨架（sandbox/mode/dispatcher/attention/claudeSdk/provider/tokenCost/subagent），现有 9 个 store 不足以覆盖 v1.0 设计稿要求。
3. **ChatPanel 体积过大**：720 行，已超出单文件 500 行质量门禁。v1.0 重构时需拆分为 Header / Messages / Input / ModeSwitcher 等子组件。
4. **TutorialPage 体积过大**：894 行，已严重超出 500 行门禁，需拆分。
5. **Provider 配置 UI 只读**：用户无法新增/编辑/删除 Provider → 无法配置 API Key → ChatPanel 无法发起对话（P0 阻塞）。
6. **Claude SDK IPC 完全未消费**：claude-sdk 类型 Provider 选了之后无响应（P0 阻塞）。
7. **沙箱审批 UI 完全缺失**：sandbox:execute 调用后 30 秒超时自动拒绝，沙箱能力完全不可用（P0 阻塞）。
8. **ToolApprovalModal 审批流闭环缺失**：仅响应审批，未监听审批请求，导致高风险工具无法触发审批弹窗。
9. **Mode 五模式未持久化**：每次启动默认 chat，用户切换后重启丢失（需 mode:set-default 写入 ConfigStore）。
10. **AttentionTracker 无 emit 钩子**：当前是单例 + 无推送，UI 需轮询 `attention:current`。

### 10.2 v1.0 重构建议

1. **第一阶段**：补齐 P0 IPC 接入（17 个 v0.9.5-pre 新增通道 + 31 个已就绪未消费 P0/P1 通道）。
2. **第二阶段**：建立 8 个新 store 骨架，统一状态管理风格（参考 `agent-store.ts` 风格）。
3. **第三阶段**：实施 P0 组件（SandboxPanel + ProviderEditor + TokenCostPanel + ModeSwitcher + ChatPanel 集成 claude-sdk + ToolApprovalModal 监听 + TutorialPage 接入 crawlStart）。
4. **第四阶段**：拆分 ChatPanel（720 行 → 多个子组件，每个 ≤ 300 行）+ TutorialPage（894 行 → 拆分）。
5. **第五阶段**：实施 P1 组件（DispatcherVisualizer + AttentionHighlight + CustomAgentManager + SystemHealthIndicator + FileOperationsMenu + LogViewer）。

### 10.3 验收标准

每个新组件需满足：
1. IPC 4 步同步铁律全部完成（main + index + preload + d.ts）
2. 三重验证：`window.electronAPI.<method>` 可调用 + 类型推导正确 + 返回值结构匹配
3. 错误路径覆盖（IPC 失败 / 主进程异常 / 窗口销毁）
4. 事件监听器在组件卸载时正确 cleanup
5. 暗色/亮色双主题适配
6. JSDoc 注释完整
7. 单文件 ≤ 500 行
