## 2. 关键技术决策（Sprint 7 中新增的工程发现）

### 2.1 `@xenova/transformers` ESM-only 兼容方案

**问题**：`@xenova/transformers@2.17.2` 是 ESM-only 模块（`package.json` 中 `"type": "module"`），CJS bundling（esbuild）无法静态 `require()`。

**尝试过的失败方案**（4 次）：
1. ❌ CJS bundle + external → `ERR_REQUIRE_ESM`
2. ❌ ESM 输出（`format: 'esm', bundle: false`）→ `ERR_MODULE_NOT_FOUND`（相对路径解析失败）
3. ❌ ESM + bundle:true + external → electron 模块不提供 `app` export
4. ❌ CJS + electron mock（`Module._load` 拦截）→ `import.meta.url` 不可用 + 仍报 ERR_REQUIRE_ESM

**最终方案**：在 `embedding-service.ts` 中用 **dynamic `import()`** 替代顶层 import：

```typescript
// 移除顶层静态 import
// import { pipeline, env } from '@xenova/transformers'  ← 删除

// 改为运行时动态加载
let transformersModule: TransformersModule | null = null
function loadTransformersModule(): Promise<TransformersModule> {
  if (transformersModule) return Promise.resolve(transformersModule)
  if (!moduleLoadPromise) {
    moduleLoadPromise = (async () => {
      const mod = await import('@xenova/transformers')  // ← dynamic import
      // ... 配置 env
      transformersModule = mod
      return mod
    })()
  }
  return moduleLoadPromise
}
```

**收益**：
1. **CJS 兼容**：esbuild CJS bundle 可正常打包（dynamic import 是运行时异步加载）
2. **懒加载**：app 启动时不加载 ONNX Runtime（首屏更快）
3. **错误恢复**：加载失败时清空 promise 允许重试
4. **测试友好**：E2E 脚本可通过 Module._load 拦截 mock

### 2.2 esbuild electron mock 用 banner 注入

**问题**：esbuild 把 `import { app } from 'electron'` 编译为顶层 `require('electron')`，但 CJS 模式下顶层 require 语句会被 hoist 到所有 import 之后执行，导致 mock 拦截器注册时 electron 已被加载（`app` 为 undefined）。

**方案**：在 esbuild 配置中用 `banner` 把 electron mock 代码注入到 bundle 最开头：

```javascript
esbuild.buildSync({
  // ...
  banner: {
    js: `
      (function () {
        const Module = require('node:module')
        const originalLoad = Module._load
        Module._load = function (request, parent, isMain) {
          if (request === 'electron') {
            return { app: { getPath: ... }, safeStorage: { ... } }
          }
          return originalLoad.call(this, request, parent, isMain)
        }
      })()
    `
  }
})
```

### 2.3 `@photostructure/sqlite-vec` 必须 external

**问题**：esbuild bundle 后，`getLoadablePath()` 返回相对路径 `dist/win32-x64/vec0.dll`，相对于 bundle 输出目录 `scripts/.cjs/` 解析，找不到 `dist/` 目录。

**根因**：`@photostructure/sqlite-vec` 用 `__dirname` 定位扩展文件，bundle 后 `__dirname` 变为输出目录，原 `node_modules/@photostructure/sqlite-vec/dist/` 找不到。

**方案**：把 `@photostructure/sqlite-vec` 加入 `external` 列表，让 Node 运行时解析（会找到 `node_modules/` 下真实路径）。

### 2.4 `tryLoadVectorExtension` 错误日志化

**问题**：原代码 `catch {}` 静默吞掉 sqlite-vec 加载错误，难以诊断。

**修复**：把 `catch` 块改为打印错误信息（生产环境降级逻辑不变）：

```typescript
} catch (err) {
  const msg = (err as Error)?.message ?? String(err)
  console.warn('[DatabaseManager] sqlite-vec 扩展加载失败，降级到关键词搜索：', msg)
  return false
}
```

## 6. 已知限制与下一步

### 6.1 已知限制

1. **测试数据集规模小**（5 条）：未覆盖 2578 条真实数据的性能边界
2. **vec0 表 rowid 必须是 INTEGER**：在 `vec0` 虚拟表中主键定义为 `id TEXT PRIMARY KEY`，但 vec0 仍要求 rowid 为整数。当前用主表 rowid 作为 content_rowid，已规避此限制
3. **Embedding 首次下载依赖网络**：BGE 模型从 hf-mirror.com 下载，断网环境需提前缓存
