### Phase B：补齐 recordBudgetAlert 写入点（P0）

**目标**：让 `budget_alerts` 表有真实数据，ModelSettings 告警历史显示真实记录。

**写入点清单**：

| 告警类型 | 写入位置 | 文件 | 触发条件 |
|----------|----------|------|----------|
| Token 日消耗超阈值 | token-stats IPC | `src/main/ipc/token-stats.ts` | 日 token 消耗 > monthlyBudget * threshold / 100 |
| LLM 响应超时 | llm client | `src/main/services/llm/client.ts` | LLM 响应时间 > 5000ms |
| LLM 连续失败 | llm client | `src/main/services/llm/client.ts` | 连续失败 3 次 |
| API Key 即将过期 | provider save | `src/main/ipc/provider-info.ts` | Provider 配置保存时检测（预留） |

**实现方式**：
- 在 token-stats 的 `token:stats` IPC 中计算日消耗，超阈值时调用 `recordBudgetAlert`
- 在 llm client 的 `analyze` 方法中，响应慢/连续失败时调用 `recordBudgetAlert`
- 从 ConfigStore 读取 `monthlyBudget` 和 `alertThreshold`（默认 2.0 / 80）

**验收**：
- 配置低阈值后触发告警，ModelSettings 告警历史显示真实记录
- `pnpm test` 全绿

## 三、前后端交接契约

### 3.1 IPC 通道契约文档

在 `docs/handoff/` 下建立：

1. **`ipc-contract.md`**：所有 193 个 IPC 通道的完整契约
   - 通道名 / 方向 / 参数 / 返回值 / 错误处理 / 调用时机
   - 按域分组（ssh / sftp / monitor / llm / credibility / ...）

2. **`frontend-backend-boundary.md`**：前后端边界
   - 后端负责：数据获取 / 业务逻辑 / IPC handler / 数据库 / 外部服务
   - 前端负责：UI 渲染 / 用户交互 / 状态管理 / IPC 调用
   - 共享：`src/shared/` 类型定义（前端不改，后端新增时需同步）

3. **`data-flow.md`**：核心数据流
   - AI 问答流：用户输入 → LLM → 工具调用 → 决策卡片 → 可信度评估
   - SSH 终端流：用户输入 → ssh:exec → 风险检查 → 执行 → 结果返回
   - 监控流：monitor:start → 心跳 → monitorData 事件 → 前端图表

### 3.2 循环工程配置

**subagent-driven-development 模式**：
- 每个 Phase 用 1 个 subagent 实施
- 主进程负责：spec 生成 → subagent 调度 → 编译门禁验证 → 归档
- subagent 负责：按 spec 实施 → 跑测试 → 自检

**编译门禁**：
```bash
pnpm typecheck:node && pnpm typecheck:web && pnpm lint && pnpm test
```
每完成一个 Task 跑一次，全绿才算完成。
