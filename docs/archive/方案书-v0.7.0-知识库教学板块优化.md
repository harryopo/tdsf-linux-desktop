## 〇、卡点深度复盘（为什么之前不顺利？）

经过对现有 10 个爬虫源 + 1 个统一服务 + 完整 UI 链路的全量分析，定位到 4 大根因：

### 卡点 1：从未真正端到端跑过
- **证据**：14 个源中只有 8 个有 `crawl*` 实现（arch/ldp/tldr/art/lc/lj/kernel/debian），其余 6 个（ubuntu-help/ms-learn/redhat-docs/digitalocean/linuxize/tecmint）只在 registry 注册但 `CRAWLERS` 映射表中**没有对应函数**
- **后果**：`tutorial:crawlStart({sourceIds: ['ubuntu-help']})` 直接抛"没有可抓取的源"
- **根因**：Phase 2 实施时只调研没动手，最后一公里未完成

### 卡点 2：无断点续传机制
- **证据**：`TutorialCrawlerService._doStart` 整个流程无 checkpoint，崩溃后必须从 0 重爬
- **后果**：Arch Wiki 月度包 500MB，下载 80% 时网络断 → 全部重来
- **根因**：设计时按"一次性任务"考虑，没考虑"长任务可恢复"

### 卡点 3：磁盘空间无管控
- **证据**：所有 `*-offline.ts` 临时文件全在 `tmpdir()`，部分文件无 `rm` 清理（`arch-wiki-offline.ts` 500MB 解压后未释放）
- **后果**：频繁抓取后 C 盘膨胀，用户无感知
- **根因**：临时文件管理未做强制清理钩子

### 卡点 4：质量过滤过于宽松
- **证据**：`upsertMany` 只用 `url hash` 去重，未做内容质量评分
- **后果**：导入大量短内容/空内容/广告页面
- **根因**：质量策略放在 UI 端"人工删除"，但导入阶段没拦截

### 卡点 5：教学板块是"列表"不是"课程"
- **证据**：`TutorialPage.tsx` 只有 8 条 mock 数据，缺章节、缺学习路径详情、缺进度跟踪
- **后果**：用户无法"学完一门课"，只能看单篇教程
- **根因**：v0.6.0 只做了"知识导入"没做"知识结构化"

### 卡点 6：书籍→Skill 路径缺失
- **证据**：用户提"后续阅读分析一些书籍，沉淀成运维skill"，但项目内**没有任何 book-parser 模块**
- **后果**：未来交付书籍时无现成 pipeline
- **根因**：v0.6 范围未规划书籍处理

## 一、目标与验收

### 1.1 目标分层

| 层级 | 目标 | 完成判据 |
|---|---|---|
| L1 可用 | 端到端跑通至少 4 个 P0 源，UI 展示真实数据 | 点击"刷新教程" → 看到 200+ 条真实教程 |
| L1 可用 | 教学板块有"详情页+章节" | 进入单门课程能看到分章节、命令示例、相关知识 |
| L2 持续 | 断点续传 | 500MB 包中断后重试不重新下载已完成部分 |
| L2 持续 | 磁盘管控 | 临时文件自动清理，UI 显示占用 |
| L3 质量 | 内容质量评分 | 短内容/广告页自动过滤，UI 标注"已过滤 X 条" |
| L3 质量 | 章节结构化 | 单篇教程可被 AI 切分为章节、配测验 |
| L4 沉淀 | 书籍→Skill pipeline | 交付 PDF/Word 时，3 步产出运维skill markdown |

### 1.2 验收硬指标

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 真实教程入库数 | ≥ 500 条（4 个 P0 源跑通） | `SELECT count(*) FROM knowledge_entries WHERE type='tutorial'` |
| 端到端抓取成功率 | ≥ 90% | 各源 `successRate` 平均 |
| 抓取中断可恢复 | ✅ | 模拟断网重试可从断点续 |
| 临时文件残留 | 0 | 抓取完成后 `os.tmpdir()` 无残留 |
| 教学板块章节渲染 | 100% 有内容 | 详情页有章节列表+代码块 |
| typecheck + build | 0 错误 | `pnpm typecheck:web && pnpm typecheck:node && pnpm build` |

### 2.2 关键数据流

#### 数据流 1：爬虫增量同步
```
用户点击 [刷新教程]
  → IPC: tutorial:crawlStart({sourceIds: ['tldr-pages']})
  → TutorialCrawlerService.start()
    → 检查 crawl_checkpoints（断点续）
    → 调用 crawlTldrPages(onProgress, signal)
      → politeFetch / git clone
      → 解析 → TutorialEntry[]
      → quality-filter 评分（丢弃 score<0.3）
    → upsertMany
      → Jaccard 去重（已有 0.6 阈值）
    → 写入 crawl_checkpoints
    → emit progress
  → IPC Push: tutorial:crawlProgress
  → UI 进度条更新
```

#### 数据流 2：教程切分为章节
```
TutorialPage 点击 [Nginx 调优]
  → TutorialDetailPage 加载
  → IPC: tutorial:get(id) + tutorial:listChapters(id)
  → AI 切分（如有 LLM key）
    → 输入：TutorialEntry.content (markdown)
    → 输出：Chapter[] = [{title, content, commands, quiz}]
    → 写 chapters 表
  → UI 渲染 左侧大纲 + 主区章节
```

#### 数据流 3：书籍→Skill（核心新流程）
```
用户拖入 PDF/Word/EPUB
  → IPC: book:import(path)
  → BookParserService
    → 1) 提取文本（pdf-parse / mammoth / epub）
    → 2) AI 提炼
       → 提取 "运维知识" = 命令 + 案例 + 排错步骤
       → LLM 提示词模板 (book→skill)
    → 3) 写知识库
       → tutorial 类型 (整章) + command_skill (可执行命令)
    → 4) 生成 SKILL.md
       → 模板：触发词 / 适用场景 / 知识清单 / 引用来源
  → IPC: book:done → 通知 SkillWorkspace
```

## 三、关键设计决策

### 决策 D1：补全 6 个未实现爬虫 vs 砍掉

**决策**：**全量补全**（理由：v0.6 调研成本已付出，缺 6 个源就交付 = 浪费）

| 源 | 爬取方式 | 优先级 | 预期产出 |
|---|---|---|---|
| ubuntu-help | 在线 (5s) | P1 | Ubuntu Server Guide 30 篇 |
| ms-learn | 在线 (2s) | P1 | Linux/Azure 50 篇 |
| redhat-docs | 在线 (10s) | P2 | RHEL 文档 50 篇 |
| digitalocean | 在线 (2s) | P2 | 通用教程 100 篇 |
| linuxize | 在线 (2s) | P3 | 100 篇 |
| tecmint | 在线 (2s) | P3 | 100 篇 |

> **策略**：先实现 ubuntu-help + ms-learn（最权威+最快），其余 4 个 v0.7.1 补完

### 决策 D2：断点续传粒度

**决策**：**HTTP Range + checkpoint 文件**（双保险）

| 层 | 机制 | 适用 |
|---|---|---|
| HTTP | Range 字节续传 | 离线包大文件（Arch Wiki 500MB） |
| 业务 | checkpoint JSON | 源级 + 文档级（已抓取的 page URL 列表） |

> **存储**：`crawl_checkpoints` 表
> ```sql
> CREATE TABLE crawl_checkpoints (
>   source_id TEXT PRIMARY KEY,
>   last_crawled_at INTEGER,
>   completed_urls TEXT,    -- JSON 数组
>   total_bytes INTEGER,    -- 已下载字节（用于 Range 续传）
>   etag TEXT,             -- HTTP 缓存
>   status TEXT             -- 'running' / 'paused' / 'done' / 'failed'
> );
> ```

### 决策 D3：磁盘空间管控

**决策**：**集中式 tempDir + 抓取后强制清理 + UI 容量展示**

- 所有临时文件统一到 `<userData>/crawler-tmp/<source-id>/`
- 抓取完成（成功/失败/取消）→ 立即 `rm -rf` 整个目录
- UI 顶部状态栏显示 "知识库占用：12.4 MB / 临时文件：120 MB（抓取后清理）"
- `crawler:diskInfo` IPC 用于查询

### 决策 D4：质量评分

**决策**：**5 维评分，0.3 阈值自动丢弃**

| 维度 | 权重 | 评分逻辑 |
|---|---|---|
| 内容长度 | 0.3 | < 200 字符 = 0.1；200-1000 = 0.5；> 1000 = 1.0 |
| 命令密度 | 0.2 | 含 ` ``` ` 代码块 = 0.8；否则 = 0.2 |
| 标题完整 | 0.15 | 有 H1/H2 = 1.0；只有 H3+ = 0.4 |
| 链接存活 | 0.15 | 至少 1 个内链 = 0.6；0 链接 = 0.3 |
| 去重检查 | 0.2 | 与已有相似度 > 0.85 = 0（已存在） |

> **UI 标注**：`CrawlResult.filtered = 12`（过滤掉 12 条低质量）

### 决策 D5：教学板块结构

**决策**：**3 层结构：课程 → 章节 → 命令**

```typescript
// 课程 = TutorialEntry (已有)
interface TutorialEntry {
  id: string
  title: string          // 课程名
  content: string        // 全部内容（备查）
  // ... 现有字段
}

// 章节 = 新增 Chapter 表
interface Chapter {
  id: string
  tutorialId: string
  order: number
  title: string          // "1. 安装 Nginx"
  content: string        // 章节 markdown
  commands: string[]     // 章节命令
  estimatedMinutes: number
}

// 命令 = 现有 command_skill 知识条目（跨课程复用）
// 学习路径 = JSON 配置（v1 写死 3 条，v2 动态生成）
```

### 决策 D6：书籍→Skill 提示词策略

**决策**：**两阶段提示词 + 模板生成 SKILL.md**

- **阶段 1（提取）**：从书中抽取 "可执行的运维知识"（命令、配置、排错步骤）
- **阶段 2（结构化）**：套 SKILL.md 模板生成

```
┌─────────────────────────────────────────────────┐
│ SKILL.md 模板                                     │
├─────────────────────────────────────────────────┤
│ # 技能名                                          │
│ ## 触发词 (3-5 个)                                │
│ ## 适用场景                                        │
│ ## 核心知识清单 (来自书籍章节)                      │
│ ## 操作命令 (来自 command_skill)                  │
│ ## 排错案例 (来自 incident_case)                  │
│ ## 参考来源 (书籍信息 + 版权)                      │
│ ## 关联教程 (来自 tutorial)                       │
└─────────────────────────────────────────────────┘
```

| 风险 | 等级 | 对策 |
|---|---|---|
| 14 个源抓取总耗时 > 4 小时 | 中 | 默认只启用 P0 5 个源，其余 opt-in |
| 磁盘被临时文件占满 | 中 | disk-budget 强制上限 1GB，超限提示 |
| 反爬升级（IP 封禁） | 高 | 严格 polite-fetch + 离线包优先 + User-Agent 标识 |
| 书籍 PDF 提取质量差 | 中 | 优先 MD/EPUB 源；PDF 用 OCR 兜底（v1.1） |
| LLM 切分章节成本 | 中 | 章节切分放后台 + 缓存（已切过不重切） |
| 14 源同步导致 SQLite 锁 | 中 | 串行抓取（已有）+ 短事务 + WAL 模式 |
