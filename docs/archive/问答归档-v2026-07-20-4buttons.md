### 2. 三项深度加固

#### 加固 A：ESM 兼容性修复（运行时阻塞）

**现象**：`pnpm dev` 启动失败，`Error [ERR_REQUIRE_ESM]: require() of ES Module ... @anthropic-ai/claude-agent-sdk/sdk.mjs not supported`

**根因**：`@anthropic-ai/claude-agent-sdk@0.3.211` 是 ESM-only（`sdk.mjs`），Electron 主进程编译后为 CommonJS（require），静态 import 触发 ERR_REQUIRE_ESM。

**修复**：
- `claude-sdk-provider.ts`：`import { query, ... }` → `import type { ... }` + 运行时 `const { query } = await import('@anthropic-ai/claude-agent-sdk')`
- `claude-sdk-tools.ts`：同样改为 type-only import + 动态 import
- `buildOptions` / `createClaudeSdkTools` / `createLinuxOpsMcpServer` 改为 async

**关键经验**：type-only import 保留编译期类型检查，运行时动态 import 加载 ESM 模块，两全其美。

#### 加固 B：OpenHands API 调研 + sessionKeyMap 预热缓存

**调研结论**：
- Docker 模式：`session_api_key` 存储在容器 env `OH_SESSION_API_KEYS_0`，每次 `searchSandboxes` 实时读取
- Remote 模式：由 runtime API 实时返回
- 主进程重启后再次 `listSandboxes`，所有 RUNNING 沙箱的 key 都能恢复

**实施方案 A（预热缓存）**：
- `warmupSessionKeyCache()` 导出函数
- 主进程启动时 `void warmupSessionKeyCache()`（不 await，不阻塞启动）
- 遍历 `searchSandboxes(100)`，将 RUNNING 沙箱的 key 缓存到 `sessionKeyMap`
- OpenHands 未启动时静默失败，下次 `sandbox:list` 时再尝试缓存

**调研文档**：`docs/OpenHands-list沙箱-session_api_key-调研报告.md`

#### 加固 C：tree-sitter-bash AST 危险命令识别

**调研结论**：
- Node.js 生态可用的 bash 解析库：bashlex（Python，需子进程）、shell-parse（纯 JS，但 AST 浅）、tree-sitter-bash（WASM，AST 深度好）
- 选定 tree-sitter-bash：web-tree-sitter（WASM 运行时）+ tree-sitter-bash（语法定义）

**实施**：
- 新建 `src/main/core/risk-engine-ast.ts`（~480 行）
- Parser 单例懒加载 WASM（开发环境从 node_modules 加载，生产环境从 process.resourcesPath 加载）
- `HIGH_RISK_COMMANDS` / `HIGH_RISK_PATTERNS` / `MEDIUM_RISK_COMMANDS` / `MEDIUM_RISK_PATTERNS` 数据集
- `extractCommands(node)` 递归遍历 AST，处理 list/pipeline/command_substitution/process_substitution
- `extractWord(node)` 处理 concatenation 节点（引号拼接绕过识别）
- `detectBase64Obfuscation(rootNode)` 检测 `base64 -d | sh` 模式
- `detectForkBomb(rootNode)` 检测 `:(){:|:&};:` 模式
- `assessWithAst(command)` 主评估函数，返回 `RiskAssessmentResult | null`（null 时降级到正则）

**6 类绕过覆盖**：
1. 命令拼接（`rm -rf / ; ls`）
2. 引号拼接（`r""m -rf /`）
3. 命令替换（`$(echo rm) -rf /`）
4. 进程替换（`< <(rm -rf /)`）
5. 变量展开（`$CMD -rf /`）
6. Base64 混淆（`echo "cm0gLXJmIC8=" | base64 -d | sh`）

**AST + 正则双层防御**：AST 解析失败时降级到 `assessCommandRiskRegex`，保证可用性。

**调研文档**：`idea-to-dev-output/27-调研-Bash命令解析库选型-危险命令识别.md`

### 4. 关键设计决策

| 决策 | 理由 |
|------|------|
| ClaudeSdkProvider 不实现 LanguageModelV2 契约 | SDK 是 ESM-only，且 agent loop 不能降级为单次 doGenerate/doStream，必须通过专属 IPC 通道调用 |

| IPC 层强制审批 | 不依赖 UI 层"自觉"实现审批弹窗（借鉴 HC-6 安全底线） |
| sessionKeyMap 预热缓存非阻塞启动 | `void warmupSessionKeyCache()` 不 await，OpenHands 未启动时静默失败 |
| AST + 正则双层防御 | AST 失败时降级到正则，保证可用性（借鉴 Postel's Law） |
| type-only import + 动态 import | 编译期类型检查 + 运行时 ESM 加载 |

### 关键设计决策

1. **P-1 ClaudeSdkChatParams 类型分层**：shared 层定义无回调的基础类型（prompt/strength/systemPrompt/cwd/includePartialMessages/correlationId），主进程内部扩展 ClaudeSdkInternalChatParams 添加 onToken/onDone/onError/mcpServers 回调。避免回调类型污染渲染进程。

2. **P-2 IPC 层强制审批**：sandbox:execute 在 IPC handler 内调用 waitForSandboxApproval()，推送 sandbox:approval-request 事件到渲染进程，等待 sandbox:approve 响应。30 秒超时自动拒绝。不依赖 UI 层"自觉"实现审批弹窗，避免 XSS 绕过。

3. **P-4 句柄模式**：session_api_key 不出主进程。sandbox:create / sandbox:list 返回前调用 cacheAndRedactSessionKey() 缓存 key 到主进程 Map + 抹除返回值。sandbox:execute 从 sessionKeyMap.get(sandboxId) 查找。sandbox:delete 删除后清理 Map。即使渲染进程被 XSS，攻击者也无法读到 key。

4. **P-2 命令危险度识别**：assessCommandRisk() 识别 low/medium/high 三级。high 包含 rm -rf 根目录 / chmod 777 / iptables / dd / mkfs / fork bomb / shutdown / killall / 直接写磁盘设备。medium 包含包管理 / 用户管理 / 服务管理 / sudo 提权 / 修改 /etc / crontab / passwd。low 为只读操作。风险等级随审批请求推送，辅助 UI 展示。

5. **P-5 token:records 设计**：主进程新增 getTokenRecords(limit) 调用，IPC 层限制 limit 范围 [1, 1000]，默认 100。用于 Token 监控面板展示明细列表 + 按 Subagent/Provider 分布图表。

6. **P-7 visualizer.ts 类型统一**：删除 visualizer.ts 中重复的 DagData/DagNode/DagEdge/DagNodeType 定义，从 @shared/agent-types 导入并用别名（DagNodeData as DagNode、DagEdgeData as DagEdge）保留旧名，让 generateDagData 函数体内的类型注解无需改动。SSOT（单一数据源）原则。

### 8. 关键设计决策

| 决策 | 理由 |
|------|------|
| 采用 Claude Subagents 文件模式 | 项目已有 8 个内部 subagent（TS 类实现，用于 LLM agent loop），外层开发协作用 Claude Subagents 文件模式不冲突 |

| 4 agent 角色分工借鉴 MetaGPT SOP | Product Manager → Architect → Engineer → QA Engineer 装配线范式 |
| 串行实施为主 | 避免文件冲突（backend 和 api 都改 src/main/ipc/） |
| reviewer 必须在最后 | 7 维审查 + 跳步检查必须在所有实施完成后进行 |

| 4 个 bug 修复都补齐了对应的真实 WASM 测试 | 质量优先：bug 修复必须配套测试，避免回归 |
| Bug 4 删除 `command: '*'` 兜底规则改为显式规则 | 兜底规则会误报只读命令（cat /etc/hosts），显式规则更精准 |
| WASM 加载失败用 vi.resetModules + vi.doMock + dynamic import 重新加载模块 | 避免影响其他测试用例的 module cache |
| 通过 sandbox:execute 间接验证 sessionKeyMap 状态（句柄模式 Map 不导出） | sessionKeyMap 是模块私有，不能直接读取，通过 IPC 错误码间接验证是合理设计 |
| 设计限制（变量展开 / 命令替换在命令名位置）显式标注 | 不掩盖静态分析的固有限制，向调用方明确说明 |
| tree-sitter-bash 容错性优先于降级 | tree-sitter 对语法错误有容错（返回部分 AST），assessWithAst 返回非 null 时不降级到正则，是设计行为 |

### 9. 关键经验总结

| 经验 | 应用场景 |
|------|---------|
| tree-sitter-bash v0.25 command 节点没有 'arguments' 字段 | 升级 tree-sitter-bash 时要重新检查 AST 结构 |
