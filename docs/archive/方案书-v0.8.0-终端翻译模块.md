## 一、需求背景

### 1.1 用户痛点

教学一体机面向 Linux 初学者，终端输出大量英文（命令名、参数、错误信息、帮助文档），学生看不懂、不敢试、效率低。

### 1.2 解决思路

**不翻译整段内容**（AI 翻译成本高、延迟大、破坏排版），改为：

> **鼠标左键滑动选中 → 弹出操作浮层（按钮组）→ 用户主动触发：本地翻译 / 发送给 AI**

### 1.3 核心价值

| 维度 | 价值 |
|------|------|
| **零依赖** | 词典下载到本地，毫秒级响应 |
| **零 token 浪费** | 默认不调 AI，仅在用户主动点击时使用 |
| **零侵入** | 不影响 xterm.js 原有功能，默认关闭 |
| **教学融合** | 翻译面板内可一键跳转对应课程章节 |

## 四、翻译算法设计

### 4.1 匹配策略（按优先级，最终实现顺序）

> ⚠️ 实施阶段对策略顺序做了关键调整：把 **option 提前到 exact-phrase 之前**，并把 **exact-phrase 限定为仅 error / phrase 类别**。原因为：`-l` / `--all` 等选项如果被 exact-phrase 优先命中会归类错误；`ls` / `chmod` 等命令如果被 exact-phrase 抢先会丢失 `command` 策略的语义清晰度。

```
1. path           路径整体识别 + 分段翻译（POSIX / Windows / ~）
   ↓
2. option         选项（含 -l / --all / 容错：用户传 "l" 也能命中 "-l"）
                  【category 守卫】仅 category='option' 的词条视为选项
   ↓
3. exact-phrase   完整短语（仅 error / phrase 类别优先，避免与 command 冲突）
   ↓
4. command        命令名（必须以字母开头 + 字母数字下划线连字符）
                  【category 守卫】仅 category='command' 的词条视为命令
   ↓
5. phrase-greedy  多词短语（贪心匹配最长）
   ↓
6. word           单个单词
   ↓
7. none           未命中（UI 层提供"问 AI"兜底）
```

**7 级策略** → 实际语义化 6 类（path / option / exact-phrase / command / phrase-greedy / word）+ none 兜底。

### 6.1 课程关联匹配

```typescript
// utils/course-matcher.ts
interface CourseHint {
  chapterId: string
  chapterTitle: string
  matchScore: number  // 0-1
}

function matchCourse(word: string, dict: Dict): CourseHint | null {
  const entry = dict.entries[word]
  if (entry?.courseChapter) {
    return { chapterId: entry.courseChapter, matchScore: 1.0 }
  }
  return null
}
```

## 十三、关键经验总结

### 13.1 翻译模块的设计哲学

> **词典驱动 + 策略链 + 缓存** 是终端翻译的最小可行方案。
> - 词典驱动：所有词条放 JSON，无运行时拼接
> - 策略链：6 种策略按优先级链式匹配，覆盖率高
> - 缓存：LRU 200 条让重复查询 < 0.1ms

### 13.2 易踩的坑

1. **策略顺序冲突**：option / command / exact-phrase 互相误匹配 → 必须用 category 守卫
2. **路径识别误判**：单个 `~` 不算路径 → `isPath` 加 PATH_SEP_REGEX 守卫
3. **引号吞词**：WORD_REGEX 不含引号导致 `grep "test"` 拆开 → 加 `"` 和 `'`
4. **缓存大小写**：`ls` 和 `LS` 应命中同一条 → key 用 lowercase
5. **私有 API 依赖**：用 xterm.js 5.5 私有 API 获取 selection 坐标 → 用 mousedown/move/up 替代

### 13.3 选词交互的稳定性

- 用 `lastMousePos` 记录鼠标位置，避免依赖 selectionchange 不带坐标
- `lastNotifiedText` 去重，避免重复回调
- 浮层用 `clamp` 防止越界（视口边缘 + 浮层宽高）
- 浮层用 `createPortal` 渲染到 body，避免父元素 overflow 裁剪
