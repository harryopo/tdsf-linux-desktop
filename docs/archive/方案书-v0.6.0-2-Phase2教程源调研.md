#### 实测数据

| 内容来源 | https://www.kernel.org/doc/html/latest/ |
| 是否提供 dump | ❌ 无官方 dump（但 git repo 公开） |

#### 风险评估（无 robots）

- **无 robots = 默认"全部允许"**（但业界共识是"保守限流"）
- **Crawl-delay**：建议 **2 秒**（参考 Phase 1 §2.1 调研）
- **风险**：中（kernel.org 是关键基础设施，避免被升级封禁）

#### 实现路径对比

| 路径 | 优点 | 缺点 |
|---|---|---|
| **A. 在线抓 HTML**（politeFetch + cheerio） | 实时 | 2s 间隔慢、5000+ 页面需很久 |
| **B. GitHub 镜像**（git clone torvalds/linux） | 快 | 仓库 4GB+、需解析 .rst 源文件 |
| **C. 只抓索引页**（列章节列表，按需抓内容） | 折中 | 需用户点开再触发（按需加载） |

#### 评估

- **合规**：✅ GPL（开源）+ 无 robots
- **风险**：中（限流 + 时长）
- **实施成本**：中（在线抓需要 politeFetch；git 镜像需要 RST 解析）
- **结论**：⚠️ **Phase 2 P1 推荐（先只抓索引）**

#### 实现计划（保守版）

```typescript
// src/main/services/tutorial/crawler/kernel-org-offline.ts
```

### 2.4 wiki.debian.org（Debian Wiki）

#### 实测数据（curl -A "TDSF-Research"）

```
wiki.debian.org/robots.txt → HTTP 200, size 424 bytes
内容：
  User-agent: *
  Crawl-delay: 20
  Disallow: /action/
```

| 项 | 值 |
|---|---|
| 主页 | https://wiki.debian.org/ |
| robots.txt | ✅ 有；**Crawl-delay: 20 秒**（超保守！） |
| Disallow | 仅 `/action/`（MediaWiki 的"动作"页） |
| License | 各页 CC BY-SA 3.0（多数）/ GFDL（少数历史页） |
| 引擎 | MediaWiki（与 Arch Wiki 同） |
| API | https://wiki.debian.org/api.php （MediaWiki API） |

#### 关键决策

- **20 秒间隔**意味着：抓 100 页 = 33 分钟；抓 1000 页 = 5.5 小时
- **策略**：用 **MediaWiki API** 拉页面列表（一次拿 500 条），再用 API 拿 wikitext，**不走 HTML**
- **可参考 Arch Wiki** 的离线 dump 模式，但 Debian Wiki **没有官方 dump**

#### 评估

- **合规**：✅ MediaWiki + CC BY-SA 3.0
- **风险**：中（20s delay 太长，1 次抓取只能拿有限页面）
- **实施成本**：中（需实现 MediaWiki API 客户端）
- **结论**：⚠️ **Phase 2 P1 推荐（API 方式 + 选择性）**

#### 实现计划

```typescript
// src/main/services/tutorial/crawler/debian-wiki-offline.ts
// 1. politeFetch https://wiki.debian.org/api.php?action=query&list=allpages&format=json&aplimit=500
// 2. 分页拉所有页面标题（aplimit=500 * 多次）
// 3. politeFetch ...&prop=revisions&rvprop=content 拿 wikitext
// 4. 用 turndown + 自定义 wikitext→md 规则
// 5. 严格 20s delay（robots 要求）
// 6. Phase 2-b 只抓"被引用最多 Top 200"页面（避免全量 8000+ 页耗时）
```

预期产出：**Top 200 被引用页面 = ~200 条教程**

#### 关键技术：wikitext → markdown

- 可用 `wtf_wikipedia` Node 库（npm: wtf-wikipedia，2k stars）
- 或自写简单 parser（仅处理标题、链接、列表、代码块）
- **推荐**：自写简单 parser（依赖轻、可靠性高）

### 10.2 GNU Manuals 暂缓说明（关键决策变更）

**原计划**：Phase 2-c 用阿里云镜像抓 GNU HTML 手册
**实测发现**：
1. `www.gnu.org` 在国内直连完全超时（15 秒无法连接）
2. `r.jina.ai`（Jina Reader 代理）也无法访问
3. `mirrors.aliyun.com/gnu/`、`mirrors.tuna.tsinghua.edu.cn/gnu/`、`mirrors.ustc.edu.cn/gnu/` **只镜像源码 tar.gz，不镜像 HTML 手册**
4. Texinfo 源 `.texi` 需要 `makeinfo` 转 HTML，依赖复杂

**结论**：GNU Manuals 在国内抓取 HTML 不可行，**Phase 2-c 暂缓**。后续可考虑：
- 方案 A：抓取 GNU 项目的 GitHub 镜像（如 git.savannah.gnu.org）→ 仅源码
- 方案 B：使用 `makeinfo` 工具链把 .texi 转 .html（依赖重）
- 方案 C：跳过 GNU Manuals（已有 jaywcjlove 覆盖大部分命令，足够日常使用）

**最终选择**：方案 C（暂缓 GNU Manuals，依赖 jaywcjlove + tldr-pages 覆盖命令速查需求）
