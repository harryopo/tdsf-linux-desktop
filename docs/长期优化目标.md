## 零 · 先说清过去为什么排期全落空

ROADMAP 顶部写着「带日期的版本号没有一条按时间表落地过」。回代码看，原因不是估时不准，是三个结构性问题：

1. **能力按通道横向铺，没有一条从「通道存在」到「界面真的调用它」的闭环判据。**
   结果是 preload 暴露 216 个键、**50 个渲染层零引用**（2026-10-24 实测；10-21 记 139，本轮整删
   attention / expectation / promptfoo 三组 12 个键、deploy 执行链 10 个键、@命令解析 3 个键、
   旧 AgentWorkflow 与裸 `llm:*` 家族 15 个键、五模式 3 个键，并把 memory 4 键接到「AI 记忆」页，
   刻度同批降到 75；其中 89→86→80→77→76→75 这几步是修量具不是还债——旧采集器认不出四种在用的写法：
   解构式接线 `const { foo } = window.electronAPI` 再调 `foo()`、别名后的可选调用 `api.foo?.()`、
   取引用回头再调 `const call = api?.close`、**换行写的链式调用**，以及别名来自访问器函数
   `const api = getElectronAPI()`（db-status-store.ts 就是这么接 db:status 的）。
   前三类各错报 3／6／1 条，第四类错报 1 条；`audit:ipc` FAIL=0 只保证不断链，不保证有人按。
   每一步降的原因记在 `scripts/audit-ipc-contract.ts` 的注释里：**修量具**（89→75）、**还债**
   （75→73 教程沙箱预检 #202、73→72 删除自己写错的那条知识 #203）、**减面**
   （72→67 整删五把没人按的管理键 #204：`monitor:stop` / `sandbox:stop` / `sandbox:detect-docker` /
   `credibility:get-calibration` / `kb:export`，每条的"那件事本来就由谁做"写进实景清单；
   67→59 整删 diagnostics 一族八把 #206：七把读键加一把没人订阅的推送，两块缓冲只写不读；
   59→50 把 Sidecar 的界面面从十一条收到两条 #207：九把里含一条能让渲染层往本地端口 POST 任意
   endpoint 的通用写入口，没人按的出口就是白给的攻击面），
   三种降不许混着讲）。
2. **调研产出了结论，结论没有转成代码里的 skip、闸或 README 的一行。**
   SSH 的 7 条基本功差距（G1–G7）原先只写在本机 reports 目录里那份 2026-10-04 的调研文档，**而那份文档不在仓库里**，
   门禁也不扫它——所以「跳板机不校验主机密钥」标了 P0 之后仍然靠人记得。
3. **所有 ratchet 都定在当天实测值上，于是「全绿」与「零余量」同时成立。**
   `as never` 69/69、旧 `--trae-*` 64/64、内联 style 109/109 —— 三条顶格（knip duplicates 已在 2026-10-20 清零）。
   门只能防回涨，不能推动下降；一动手重构就立刻红，于是重构被推迟。

**因此这份清单的第一原则是：先判决、再下降、最后才加新能力。**
