## 零 · 先说清过去为什么排期全落空

ROADMAP 顶部写着「带日期的版本号没有一条按时间表落地过」。回代码看，原因不是估时不准，是三个结构性问题：

1. **能力按通道横向铺，没有一条从「通道存在」到「界面真的调用它」的闭环判据。**
   结果是 preload 暴露 273 个键、**128 个渲染层零引用**；`audit:ipc` FAIL=0 只保证不断链，不保证有人按。
2. **调研产出了结论，结论没有转成代码里的 skip、闸或 README 的一行。**
   SSH 的 7 条基本功差距（G1–G7）写在 `docs/reports/SSH连接工程调研-20261004.md`，而那份文档**不在仓库里**，
   门禁也不扫它——所以「跳板机不校验主机密钥」标了 P0 之后仍然靠人记得。
3. **所有 ratchet 都定在当天实测值上，于是「全绿」与「零余量」同时成立。**
   `as never` 76/76、knip duplicates 16/16、旧 `--trae-*` 64/64、内联 style 109/109 —— 四条顶格。
   门只能防回涨，不能推动下降；一动手重构就立刻红，于是重构被推迟。

**因此这份清单的第一原则是：先判决、再下降、最后才加新能力。**

## 三 · SSH 基本功（主打卖点上最薄的地方）

差距清单在 `docs/reports/SSH连接工程调研-20261004.md`（**该文件未入库**，见 §六）。

- **G2 无 `~/.ssh/config` 解析**：全仓 `ssh_config|IdentityFile|ProxyJump` 无解析实现；
  后果是用户已有的 Host/ProxyJump 配置在这里不生效。目标：解析 Host/HostName/User/Port/IdentityFile/ProxyJump，
  `Match` 显式不支持并在界面说明（`Match exec` 会在用户 shell 里执行命令）。
- **G3 无 ssh-agent / Pageant**：`src/main/services/ssh` 里 `SSH_AUTH_SOCK|agent:` 0 命中，私钥明文进内存；
  ssh2 原生支持 `agent`。目标：优先走 agent，落到文件密钥时提示。
- **G6 终端渲染器落后一代**：`@xterm/xterm` 5.5 且无 webgl 附件（`TerminalView.tsx:22` 的 import 被注释掉）。
  目标：量一次大输出滚动帧数，再决定升 6.x 还是开 canvas。
- **G5 keepalive 静态、重连不保状态**：目标是在断线重连后恢复标签与会话上下文。

  抄本永远比正本先漂（本轮就抓到 README 与宣传页的用例数同时过期）。
