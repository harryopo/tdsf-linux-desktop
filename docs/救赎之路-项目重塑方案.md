# 救赎之路 · tdsf-linux-desktop 项目重塑方案

> 生成时间：2026-07-23
> 基于：v2.3 外部独立审查报告 + 五维开源调研
> 核心理念：**删比加更重要 · 少即是多**

---

## 一、诊断摘要

外部审查揭示的**根本问题**不是"代码写得不好"，而是**三个维度的系统性失控**：

```
          规范失控                  流程失控                  产品失控
    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
    │ CLAUDE.md 350行  │    │ 33% commit 是归档 │    │ 92依赖 + 3 Sidecar│
    │ AGENTS.md 800行  │    │ 5个归档目录6,766行│    │ D-S + PCR5 + ECE │
    │ 22条硬约束       │    │ 循环→审计→归档→遗忘│    │ EU AI Act 合规   │
    │ B级=WIP绕过      │    │ "文档同步"占15%评分│    │ 安装包 600-800MB │
    └────────┬────────┘    └────────┬────────┘    └────────┬────────┘
             │                      │                      │
             └──────────────────────┼──────────────────────┘
                                    │
                          ┌─────────▼─────────┐
                          │  根本因果链：       │
                          │  比赛叙事 → 堆叠技术栈│
                          │  → 技术栈需要管理规范  │
                          │  → 规范需要审查验证    │
                          │  → 验证需要归档证明    │
                          │  → 归档吃掉开发时间    │
                          │  → 功能永远做不完      │
                          └───────────────────┘
```

**一句话根因**：项目把"管理 AI 写代码"的流程建设当成了产品本身。你不是在做一个 Linux 教学工具，你是在做一个"如何用 AI 做 Linux 教学工具"的元项目。

---

## 二、救赎三原则

### 原则 1：删比加重要

> *"Code is a liability, not an asset."* — 每行代码都是未来的维护负债

### 原则 2：先验证再架构

> *"If you're not embarrassed by your first version, you shipped too late."* — Reid Hoffman

Dropbox 用 3 分钟视频验证需求才写代码。Airbnb 用 WordPress 博客手动处理支付验证模式。你的项目需要先证明"有人真的需要用 AI 学 Linux"——然后再谈 D-S 证据理论。

### 原则 3：为删而建

> *"Perfection is achieved not when there is nothing more to add, but when there is nothing left to take away."* — Saint-Exupéry

每加一个功能之前，先问：能不能删一个现有功能？

---

## 三、具体执行：90 天重塑路线

```
Week 1-2: 冰冻期（停止加功能，只做减法）
Week 3-4: 重构期（精简到可发布的 MVP）
Week 5-8: 验证期（找真实用户试用）
Week 9-12: 迭代期（基于反馈做小步迭代）
```

### Phase 1：冰冻期（Week 1-2）

**目标**：冻结所有新功能，只做减法。目标缩减代码量 40%。

#### 第 1 步：砍 Python Sidecar（砍 2 留 1）

| Sidecar | 功能 | 判断 | 理由 |
|---------|------|------|------|
| sidecar-a (Drain3) | 日志模板提取 | ✅ 保留 | 日志分析是核心功能 |
| sidecar-b (DoWhy) | 因果推断 | ❌ 删除 | Linux 教学不需要因果推断 |
| sidecar-c (AgentScope) | 多 Agent 协作 | ❌ 删除 | Mastra 已做 Agent 编排 |

**操作**：
```bash
rm -rf sidecar-b/ sidecar-c/
rm docs/SIDECAR-B-CAUSAL-INFERENCE.md docs/SIDECAR-C-MULTI-AGENT.md
# sidecar/health.ts 中删除 sidecar-b/c 健康检查
# IPC channels 中删除 sidecar:*-b 和 sidecar:*-c 相关通道
```

**预期效果**：部署复杂度降低 60%，安装包减少 ~300MB（Python 环境）。

#### 第 2 步：砍过度学术算法

| 模块 | 判断 | 理由 |
|------|------|------|
| D-S 证据理论 | ⚠️ 降级 | 从 4 引擎降为简单规则，保留接口可日后恢复 |
| PCR5 融合规则 | ⚠️ 降级 | 同上 |
| ECE 校准 | ❌ 删除 | 教学工具不需要温度缩放校准 |
| Temperature Scaling | ❌ 删除 | 同上 |
| EU AI Act 合规审计格式化 (Art.11/12/13) | ❌ 删除 | 比赛不需要 |
| Langfuse 全链路 trace | ⚠️ 降级 | 改为 DEV-only，生产不开启 |

**操作**：
```bash
# 删除 ECE 校准模块
rm -rf src/main/core/agent/credibility/calibration/
# 删除 EU AI Act 格式化器
rm src/main/core/agent/credibility/audit/formatters.ts
# 简化可信度引擎为规则引擎
# 高风险命令 = 直接拦截（保留现有黑名单）
# 中风险命令 = 弹窗确认
# 低风险命令 = 直接放行
```

**预期效果**：可信度模块从 ~2,000 行缩减到 ~300 行。删除 ~1,700 行死代码。

#### 第 3 步：砍不用的 npm 依赖

**审计命令**（需要先安装 depcheck 或 knip）：
```bash
npx depcheck 2>&1 | head -50
# 或
npx knip --dependencies
```

**预估可砍依赖**：

| 依赖 | 判断 | 理由 |
|------|------|------|
| `@anthropic-ai/claude-agent-sdk` | ❌ 删除 | Vercel AI SDK 已够用 |
| `@ai-sdk/google` | ❌ 删除 | 主力是火山方舟 + DeepSeek |
| `@xenova/transformers` | ❌ 删除 | 浏览器端 ML 对运维工具无场景 |
| `three` + `@types/three` | ❌ 删除 | 3D 渲染无场景 |
| `reactflow` | ⚠️ 评估 | 流程图是否为核心交互？ |
| `turndown` + `cheerio` | ⚠️ 合并 | 保留一个 HTML 处理库 |
| `dompurify` | ✅ 保留 | XSS 防护（安全必备） |
| `tree-sitter-bash` + `web-tree-sitter` | ⚠️ 评估 | 终端语法高亮用，保留 |

**预期效果**：从 92 依赖降到 ~50。node_modules 从 ~200MB 降到 ~100MB。

#### 第 4 步：合并规范文档

```
CLAUDE.md (350行) + AGENTS.md (800行) = 1,150 行规则

                     ↓ 合并、删重复、砍"建议"

                CODING.md (80行核心规则)

旧版归档：
mv CLAUDE.md docs/archive/CLAUDE-v2.4.md
mv AGENTS.md docs/archive/AGENTS-v8.6.md
```

**CODING.md 应包含（80 行以内）**：
1. 技术栈（10 行）：Electron 30 + React 18 + TypeScript strict + Antd 5 + Zustand
2. 目录结构（10 行）：main/preload/renderer/shared
3. IPC 铁律（5 行）：main → ipc/index → preload → electron.d.ts
4. 安全底线（10 行）：脱敏 + 高危命令拦截 + XSS 防护
5. 质量门禁（10 行）：typecheck:node + typecheck:web + lint + test 全部 green
6. CSS 约定（10 行）：用 var(--trae-*)，禁止硬编码
7. Git 约定（10 行）：commit 格式 + PR 流程
8. 环境要求（5 行）：Node 18+, pnpm, Python 3.11+（仅 sidecar-a）
9. 快速开始（10 行）：pnpm install && pnpm dev

**全部。没有 B 级约束。没有"开发阶段可临时违反"。没有 WIP 标注。编译器不通过就不能合并。**

### Phase 2：重构期（Week 3-4）

#### 第 6 步：建立构建门禁

```yaml

on: [push, pull_request]
jobs:

    steps:
      - run: pnpm typecheck:node
```

### Phase 3：验证期（Week 5-8）

**目标**：找 3-5 个真实用户试用，收集反馈，证明"有人需要这个"。

#### 用户招募

- 深圳信息职业技术大学 Linux 课程的同学（3-5 人）
- 找一个 Linux 实训课老师

#### 测试脚本

```
给用户一个干净的 Windows 笔记本。
安装包放桌面上。

任务：
1. 双击安装（记录安装时间）
2. 启动应用（记录冷启动时间）
3. 连接到远程 Linux 服务器（提供 IP/账号）
4. 用 AI 助手问 "怎么查看系统负载？"
5. 执行 AI 建议的命令
6. 上传一个文件到服务器
7. 查看监控面板

全程不给人帮助。记录所有"卡住"的时刻。
```

#### 验收标准

- 安装时间 < 2 分钟
- 冷启动 < 5 秒
- 用户能自行完成"SSH 连接 + AI 问答 + 文件上传"三步核心流程
- 安装包 < 250MB

---

### Phase 4：迭代期（Week 9-12）

基于用户反馈，每 2 周迭代一次，每次迭代只加 **1 个功能**。

| 迭代 | 可能的改进方向（取决于反馈） |
|------|--------------------------|
| v3.1 | 改进 AI 回答质量（提示词优化） |
| v3.2 | 增加命令历史自动记录 |
| v3.3 | 增加教程书签功能 |
| ... | 视用户反馈决定 |

**核心纪律**：每加一个功能，必须先删一个不用的。保持功能数量不增加。

## 四、新规范体系（CODING.md 草案）

```markdown
# CODING.md - 开发规范（80 行）

## 技术栈
Electron 30 + React 18 + TypeScript strict + Antd 5 + Zustand + ssh2 + xterm.js

## 目录结构
- src/main/      → 主进程：IPC handlers, services, core
- src/preload/   → 预加载：contextBridge 暴露 API
- src/renderer/  → 渲染进程：React 组件、页面、stores
- src/shared/    → 共享类型和常量

## IPC 铁律（不可绕过的 4 步）
1. main/ipc/{domain}.ts 定义 handler
2. shared/ipc-channels.ts 定义常量
3. preload/{domain}.ts 暴露 API
4. types/electron.d.ts 声明类型
缺一步 = 不能合并。

## 安全底线
1. 所有 catch 块的 error.message 写入日志前必须脱敏
2. SSH exec 必须经过高危命令黑名单（12 条正则）
3. 渲染层 dangerouslySetInnerHTML 必须经 DOMPurify.sanitize
4. .env / .ssh/ / *_key 相关内容在日志中自动替换为 [REDACTED]

## 质量门禁（CI 硬编码，不靠人记）
- pnpm typecheck:node → exit 0
- pnpm typecheck:web → exit 0
- pnpm lint → 0 errors
- pnpm test → 全量通过
- pnpm build:win → 成功生成 .exe

## CSS 约定
所有颜色使用 var(--trae-*) 引用，禁止 #ffffff / #fafafa / #0071e3 等硬编码

## Git 约定
- commit: type(scope): description（feat/fix/docs/refactor/test）
- 分支: 直接 main，不需要多余分支策略
- 不在 commit message 中带 session ID

## 环境要求
- Node 18+
- pnpm 9+
- Python 3.11+（仅 sidecar-a 需要）
- Windows 11 + VS Build Tools

## 快速开始
pnpm install
pnpm dev
```

## 七、最后的话

> 你不是在做一个"有 D-S 证据理论 + PCR5 融合 + ECE 校准 + EU AI Act 合规 + MCP Server + Langfuse 全链路 trace 的 AI Agent 平台"。
>
> 你是在做一个**帮助 Linux 初学者不怕命令行的工具**。
>
> 如果一个工具需要 600MB 安装包、3 个 Python 环境、92 个 npm 依赖才能跑起来——那它不是帮助初学者，它本身就是初学者要翻越的另一座山。

**删掉不需要的。留下核心的。发布。找用户。迭代。**
