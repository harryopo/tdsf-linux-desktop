## 三、Phase C：教程 embedding 异步分批回填（P1-9）

### 3.1 问题诊断

**现状**（`src/main/ipc/tutorial.ts:264-290`）：
- `tutorial:backfill-embeddings` handler 同步 await `repo.backfillEmbeddings()`
- 2578 条教程回填需 1-3 分钟，期间 IPC 阻塞，渲染层 UI 冻结
- 无进度推送，用户无法知道回填进度
- 无取消机制，一旦启动无法中止

**目标**：
1. 改为异步后台任务（启动后立即返回 taskId）
2. 通过 `tutorial:backfill-progress` push 通道推送进度
3. 支持取消（`tutorial:backfill-cancel`）
4. 支持状态查询（`tutorial:backfill-status`）
5. 断点续传（`WHERE embedding IS NULL` 自动跳过已处理）

### 3.2 调研结论（参考 v2.5-research-backend-enhancement.md）

| 关键约束 | 来源 | 应对 |
|---------|------|------|
| better-sqlite3 transaction 内禁止 async/await | 官方 API 文档 | 推理在事务外，写入在事务内 |
| Transformers.js embedBatch 已支持 ONNX 内部 batching | xenova/transformers | 复用 EmbeddingService.embedBatch |
| Electron IPC Pattern 3：webContents.send 主→渲染 | 官方文档 | 复用 scheduler.ts 的 pushToRenderer 模式 |
| 2578 条 / 100 页 = 26 次进度推送 | 计算合理 | 避免过细推送导致渲染卡顿 |

### 3.3 实现方案

#### 3.3.1 新增模块：`src/main/services/tutorial/backfill-service.ts`

```typescript
export interface BackfillProgress {
  taskId: string
  processed: number
  total: number
  failed: number
  pct: number          // 0-1
  currentBatch: number
  eta: number          // 剩余 ms（估算）
  status: 'running' | 'completed' | 'cancelled' | 'failed'
}

export class EmbeddingBackfillService {
  private static instance: EmbeddingBackfillService | null = null
  private running = false
  private cancelled = false
  private currentTaskId: string | null = null

  // 单例 + 状态守卫（防止并发启动）
  static getInstance(): EmbeddingBackfillService { ... }

  // 启动异步分批回填（不阻塞 invoke 返回）
  async start(db: DatabaseManager, taskId?: string, pageSize?: number, inferenceBatch?: number): Promise<BackfillProgress>

  // 取消（标记 cancelled，下页检查后退出）
  cancel(): void

  // 状态查询
  getStatus(): { running: boolean; taskId: string | null }

  // 推进度到所有渲染窗口
  private pushProgress(p: BackfillProgress): void
}
```

**关键设计**：
1. **分页查询**：每次 `LIMIT 100`，`WHERE embedding IS NULL` 自动断点续传
2. **事务边界**：embedding 推理在事务外（async），写入在事务内（同步）
3. **取消机制**：`cancelled` 标记，每页处理后检查
4. **错误隔离**：单批失败记录 `failed` 计数，继续下一页
5. **ETA 估算**：`elapsed / processed * remaining`
6. **单例 + 状态**：`isRunning()` 防止并发启动

#### 3.3.2 IPC 通道扩展

**新增 3 个 invoke 通道 + 1 个 push 通道**：

| 通道 | 方向 | 用途 | 参数 | 返回值 |
|------|------|------|------|--------|
| `tutorial:backfill-start` | invoke | 启动异步回填 | `{ pageSize?: number, inferenceBatch?: number }` | `{ ok: boolean, taskId: string, error?: string }` |
| `tutorial:backfill-cancel` | invoke | 取消回填 | 无 | `{ ok: boolean }` |
| `tutorial:backfill-status` | invoke | 查询状态 | 无 | `{ running: boolean, taskId: string \| null }` |
| `tutorial:backfill-progress` | push | 进度推送（主→渲染） | 无（载荷由主进程构造） | `BackfillProgress` |

**保留旧通道**：`tutorial:backfill-embeddings` 保持不变（向后兼容），但内部委托给 `EmbeddingBackfillService.start()` 同步等待完成。

## 六、循环工程开发流程

### 6.1 subagent-driven-development 模式

```
主进程（本 AI）
  │
  ├── 1. spec 生成（本方案书）
  ├── 2. Task 分解（TodoWrite）
  ├── 3. 每个 Task 用 subagent 实施（可选）
  │      ├── spec-reviewer：审查实施前 spec
  │      ├── implementer：按 spec 编码
  │      ├── code-quality-reviewer：代码质量审查
  │      └── fix-implementer：修复审查问题
  ├── 4. 编译门禁验证（typecheck + lint + test）
  └── 5. 归档 + 交接 + 记忆
```

### 6.2 编译门禁（五绿全过才算完成）

```bash
pnpm typecheck:node   # 主进程 TypeScript 类型检查
pnpm typecheck:web    # 渲染进程 TypeScript 类型检查
pnpm lint             # ESLint 代码规范
pnpm test             # Vitest 单元测试
pnpm build:win        # electron-builder 打包（可选，里程碑时跑）
```

### 6.3 执行顺序

```
Phase C (P1-9 异步回填)
    ↓
Phase D1 (hybrid-search 测试迁移)
    ↓
Phase D2 (path-recommender 注释清理)
    ↓
Phase D3 (xxx 占位替换)
    ↓
Phase E (归档 + 交接 + 记忆)
```

每个 Task 完成后：
1. 跑编译门禁三绿（typecheck:node + typecheck:web + lint）
2. 跑相关测试
3. 更新本方案书状态
4. git commit（conventional commit 格式）

### 6.4 风险与缓解

| 风险 | 缓解 |
|------|------|
| 前端 AI 并行修改导致冲突 | 只改 src/main/ 和 src/shared/，不改 src/renderer/ |
| better-sqlite3 事务内禁止 async | 推理在事务外，写入在事务内（已验证） |
| EmbeddingService 单例并发（回填 + 实时检索） | 回填期间检索会排队，可接受（比赛演示场景低并发） |
| 进度推送频率 | 2578 条 / 100 页 = 26 次推送，频率合理 |
| 取消机制竞态 | cancelled 标记 + 下页检查，单页内不会中止 |
