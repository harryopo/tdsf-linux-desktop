## 摘要

v1.0 重构的核心目标是将"FinalShell 风格远程带 AI 小软件"重构为"IDE 形式 Linux 运维工作台"。重构基于已通过验证的 20 页面设计稿（`tdsf-linux-redesign`），与现有 v0.9.5-pre 项目（89+17 个 IPC + 39 组件 + 9 store）进行融合。

**核心决策**（详见第一章）：
1. **主参考**：redesign（英文命名 + 121 具名图标 + 工程化体系已建立）
2. **技术栈**：保留 React 18 + Zustand + React Router 6，引入 Tailwind CSS v4 + shadcn/ui + Lucide，AntD 5 渐进式退役（保留 Modal/Form/Table 等复杂组件作为底层，通过 ConfigProvider token 覆盖）
3. **IPC 适配**：preload 层建立 `IpcToRestBridge`，新组件用 fetch('/api/*') 透明映射 IPC，老组件保持 `window.electronAPI.*` 调用
4. **路由**：React Router v6 Data Router 模式，6 条 → 20 条，含路由守卫

**工作量估算**：新建约 85 文件 / 改造约 18 文件 / 新增约 65 测试 / 总代码量约 18000 行。

**风险等级**：P0 风险 4 项（必须先决策）+ P1 风险 5 项（实施中决策）+ 待澄清问题 7 项（需用户确认）。

## 一、重构策略决策

### 1.1 主参考选择

**决策：以 `tdsf-linux-redesign` 作为 v1.0 重构的主参考。**

**理由**：

| 维度 | 参考资料 | redesign | 优势方 |
|------|---------|----------|--------|
| 文件命名 | 中文（`工作台.html`） | 英文（`workbench-ai.html`） | redesign（Git 友好、跨平台） |
| 图标库 | 70 个编号图片（`image_N_hr9ljb.svg`） | 121 个具名图标（`shield.svg` 等） | redesign（语义化、可维护） |
| 工程化体系 | 无配套文档 | 自检报告 + 前端架构文档 + 接口说明文档 + 项目记忆 | redesign |
| 验证脚本 | 无 | `scan-design-directory.mjs`（0 错误通过） | redesign |
| 视觉一致性 | 与 redesign 完全等价（字节级对比仅差 `<html>` 标签的 `data-theme` 属性） | 同左 | 平 |
| Critical 问题修复 | 无 | C1/C2/C3 文档层已修复 | redesign |

**参考资料保留价值**：
- `data-theme="dark"` 属性设计（为未来浅色模式预留扩展点）
- 70 个 SVG 图标源文件（用于追溯设计意图）
- 设计稿导出工具的完整产物（用于版本追溯）

**实施约束**：以 redesign 的 20 个 HTML 为页面模板基线，但需修复 redesign 自检报告中的 3 个 Critical + 12 个 High 问题（详见第六章）。

### 1.2 技术栈取舍

**决策：选项 B（渐进式）—— 保留 React，引入 Tailwind CSS v4 + shadcn/ui + Lucide，AntD 5 渐进式退役。**

#### 三个选项对比

| 选项 | 描述 | 优势 | 劣势 | 工作量 |
|------|------|------|------|--------|
| A | 保留 React + AntD 5，把设计稿 HTML 翻译成 AntD 组件 | 现有 39 组件全部保留 | AntD 与 TRAE 风格差异大（圆角 8px vs 4/6/8/10、阴影系统、配色），翻译后视觉保真度低；用户偏好"不要 AI 味设计"，AntD 默认风格偏 AI 味 | 中（视觉保真度低） |
| **B** | **保留 React，引入 Tailwind + shadcn/ui + Lucide，AntD 渐进退役** | **视觉保真度高（设计稿原生 Tailwind）；复用现有 39 组件 + 9 store；shadcn/ui 是 React 生态最契合 Tailwind 的组件库** | **需双轨并行（AntD + Tailwind 共存期），需建立迁移规范** | **中高（可控）** |
| C | 完全按设计稿原生（HTML + Tailwind CDN + Lucide + 少量 JS），放弃 React | 视觉 100% 保真 | 现有 39 组件 + 9 store 全部重写，工作量极高；放弃 React 生态（Zustand/React Router/Recharts 等都需替换） | 极高（不推荐） |

### 1.3 IPC ↔ REST 适配层

**决策：选项 A —— 在 preload 层建立 `IpcToRestBridge`，让设计稿的 fetch('/api/...') 透明映射到 IPC。**

#### 三个选项对比

| 选项 | 描述 | 优势 | 劣势 | 推荐度 |
|------|------|------|------|--------|
| **A** | **preload 层 IpcToRestBridge，fetch('/api/*') 透明映射 IPC** | **新组件可按设计稿 REST 形态编写；老组件保持 window.electronAPI.* 不变；不引入额外进程** | **需维护映射表；SSE/WS 需用 EventEmitter 模拟** | **★★★★★** |
| B | 直接把设计稿 fetch 调用改写为 window.api.xxx IPC 调用 | 实现简单 | 设计稿 69 接口的 REST 形态被破坏；新组件代码与设计稿脱节；不利于后续 Web 化 | ★★ |
| C | 主进程启动 Express/Koa 服务器，渲染层用真实 REST | 真正的 REST 形态；利于后续 Web 化 | 引入额外 HTTP 服务器，启动延迟 + 内存开销；JWT 鉴权复杂化；CSP 需放行 localhost | ★★ |

#### 选项 A 详细方案

**架构**：

```
┌─────────────────────────────────────────────────────────┐
│ 渲染进程 (React)                                         │
│  ├─ 新组件：fetch('/api/servers') → IpcToRestBridge     │
│  └─ 老组件：window.electronAPI.sshConnect() → IPC       │
├─────────────────────────────────────────────────────────┤
│ Preload (IpcToRestBridge)                                │
│  ├─ fetch(path, opts) 拦截器                            │
│  │   ├─ /api/servers        → server:list / server:save │
│  │   ├─ /api/ai/chat (SSE)  → agent:chat + onAgentChunk │
│  │   ├─ /api/ssh/connect(WS)→ ssh:connect + onTerminal* │
│  │   └─ ...（共 69 个映射规则）                          │
│  └─ window.electronAPI.* 透传（老组件兼容）              │
├─────────────────────────────────────────────────────────┤
│ 主进程 (Electron IPC)                                    │
│  └─ 89 个 ipcMain.handle + 17 个 v0.9.5-pre 新增        │
└─────────────────────────────────────────────────────────┘
```

**核心实现**（伪代码）：

```typescript
// src/preload/api-bridge.ts
const routeMap: Record<string, { method: string; handler: (args: any) => Promise<any> | EventEmitter }> = {
  'GET /api/servers':           { method: 'invoke', handler: () => window.electronAPI.serverList() },
  'POST /api/servers':          { method: 'invoke', handler: (body) => window.electronAPI.serverSave(body) },
  'POST /api/ssh/connect':      { method: 'stream', handler: (body) => createSshEventStream(body) },
  'POST /api/ai/chat':          { method: 'sse',    handler: (body) => createChatSSEStream(body) },
  'POST /api/decision/confidence': { method: 'invoke', handler: (body) => window.electronAPI.credibilityAssess(body) },
  // ... 共 69 个映射规则
};

window.fetch = new Proxy(window.fetch, {
  apply(target, thisArg, args) {
    const [url, opts] = args;
    const route = `${opts?.method || 'GET'} ${url}`;
    const mapped = routeMap[route];
    if (mapped) return handleBridge(mapped, opts);
    return Reflect.apply(target, thisArg, args);  // 透传非 /api/* 请求
  }
});
```

**SSE/WS 模拟**：
- SSE：用 EventEmitter + ReadableStream 模拟 `text/event-stream` 响应
- WS：用 EventEmitter 模拟 WebSocket 接口（`onopen/onmessage/onclose`）

**映射表维护**：建立 `src/preload/api-routes.ts` 集中管理 69 个映射规则，含 TypeScript 类型校验。

**兼容策略**：老组件（39 个）保持 `window.electronAPI.*` 调用不变，新组件统一用 `fetch('/api/*')`。
