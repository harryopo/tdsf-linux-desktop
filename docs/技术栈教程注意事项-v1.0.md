# 第 1 篇：Electron 桌面应用开发

## 1.1 三进程架构（必须理解）

```
┌────────────────────────────────────────────────────────────┐
│                       Electron 进程模型                      │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  ┌──────────────┐  IPC  ┌──────────────┐  IPC  ┌────────┐  │
│  │   Main       │◄────►│   Preload    │◄────►│Renderer│  │
│  │ (Node.js)    │      │ (Bridge)     │      │(Chromium)│ │
│  │              │      │              │      │         │  │
│  │ • 主窗口     │      │ • 暴露白名单  │      │ • UI    │  │
│  │ • 系统服务   │      │ • 不持业务    │      │ • 组件  │  │
│  │ • fs/ssh/db  │      │ • 仅 context │      │ • 状态  │  │
│  │              │      │   Bridge     │      │         │  │
│  └──────────────┘      └──────────────┘      └────────┘  │
│         ▲                                            ▲    │
│         │                                            │    │
│         └────────── Worker Threads / Utility Process ─┘    │
└────────────────────────────────────────────────────────────┘
```

## 1.2 强制安全配置（OWASP + Electron 官方）

```typescript
// electron.vite.config.ts 或 BrowserWindow 创建处

  },
```

## 1.3 IPC 通信 4 步同步（项目硬约束）

```typescript
// 第 1 步：主进程定义 handler
// src/main/ipc/ssh.ts
import { ipcMain } from 'electron'
export function registerSshIpcHandlers(): void {
  ipcMain.handle('ssh:connect', async (_event, config) => {
    return await sshManager.connect(config)
  })
}

// 第 2 步：主进程 ipc/index.ts 注册
// src/main/ipc/index.ts
import { registerSshIpcHandlers } from './ssh'
export function registerAllIpcHandlers(): void {
  registerSshIpcHandlers()  // ✅ 必须 import + 调用
}

// 第 3 步：preload 暴露（扁平化，不嵌套）
// src/preload/index.ts
import { contextBridge, ipcRenderer } from 'electron'
contextBridge.exposeInMainWorld('electronAPI', {
  sshConnect: (config) => ipcRenderer.invoke('ssh:connect', config),  // ✅ 扁平
  // ❌ 错误：ssh: { connect: () => ipcRenderer.invoke('ssh:connect') }（嵌套崩溃）
})

// 第 4 步：electron.d.ts 类型声明
// src/preload/index.d.ts
export interface ElectronAPI {
  sshConnect: (config: SshConfig) => Promise<SshSession>
}
declare global {
  interface Window { electronAPI: ElectronAPI }
}
```

## 1.4 跨进程类型（共享类型放 src/shared/）

```typescript
// ❌ 反模式：在 renderer import 主进程类型
// src/renderer/src/components/X.tsx
import type { SshConfig } from '../../../main/services/ssh/types'  // TS2307 报错
// 根因：tsconfig.web.json 的 include 不包含 src/main/

// ✅ 正确：跨端类型放 src/shared/
// src/shared/ssh-types.ts
export interface SshConfig { host: string; port: number; username: string; ... }

// 主进程 services/types.ts 用 re-export 兼容
// src/main/services/ssh/types.ts
export type { SshConfig } from '../../../shared/ssh-types'

// 渲染端直接 import
// src/renderer/src/components/X.tsx
import type { SshConfig } from '@/shared/ssh-types'  // ✅
```

## 1.5 常见踩坑

| 问题 | 症状 | 解决 |
|------|------|------|
| 主进程 IPC 就绪 ≠ UI 就绪 | 编译 4 绿，UI 空白 | 必须 E2E 验证（`pnpm test:e2e`） |
| preload 嵌套 API | `window.api.x.y()` undefined | **扁平化**所有 API |
| Sandbox 模式下用了 fs | 启动失败 | preload 只能 `electron` + `contextBridge` |
| BrowserWindow 多次创建 | 内存泄漏 | 用单例模式 + 复用 |

# 第 2 篇：React 18 + TypeScript 5.4

## 2.1 函数组件 + Hooks（项目铁律）

```typescript
// ✅ 函数组件 + 类型注解
interface ChatPanelProps {
  sessionId: string
  onSend: (text: string) => void
}

export function ChatPanel({ sessionId, onSend }: ChatPanelProps) {
  const [text, setText] = useState('')
  const messages = useMessages(sessionId)  // 自定义 Hook

  // ✅ 派生值用 useMemo
  const visibleMessages = useMemo(
    () => messages.filter(m => !m.hidden),
    [messages]
  )

  // ✅ 事件回调用 useCallback
  const handleSend = useCallback(() => {
    onSend(text)
    setText('')
  }, [text, onSend])

  return <div>...</div>
}
```

## 2.2 性能优化（Vercel 57 条规则精选）

| 场景 | 规则 | 示例 |
|------|------|------|
| 大量列表 | `React.memo` + 稳定 `key` | `<Row key={item.id} item={item} />` |
| 重组件 | `React.lazy` + `Suspense` | `const Heavy = lazy(() => import('./Heavy'))` |
| 计算密集 | `useMemo` 缓存 | `const list = useMemo(() => compute(items), [items])` |
| 事件回调 | `useCallback` 稳定引用 | `const onClick = useCallback(() => ..., [deps])` |
| 大状态 | Zustand selector 订阅 | `useStore(s => s.x)` 而非 `useStore()` |
| 副作用 | 用事件而非 effect | `onClick={handler}` 而非 `useEffect(() => handler(), [])` |

## 2.3 类型安全（TS 5.4 strict）

```typescript
// ✅ 用 Zod 做运行时校验
import { z } from 'zod'

const SshConfigSchema = z.object({
  host: z.string().min(1),
  port: z.number().int().min(1).max(65535),
  username: z.string().min(1),
})

type SshConfig = z.infer<typeof SshConfigSchema>  // 类型自动派生

// 在 IPC handler 入口校验
ipcMain.handle('ssh:connect', async (_e, raw) => {
  const config = SshConfigSchema.parse(raw)  // 抛 ZodError 自动转 400
  return await sshManager.connect(config)
})
```

## 2.4 EventEmitter 类型技巧

```typescript
// ✅ emit 方法签名自动注入 type 字段
class Foo extends EventEmitter {
  // 单事件签名
  emit(event: 'status', payload: { sessionId: string; status: string }): boolean
  emit(event: string, payload: any): boolean  // fallback
}

// 直接传 payload，不要 satisfies
this.emit('status', { sessionId, status: 'thinking' })  // ✅
// ❌ 错误：this.emit('status', {...} satisfies LoopEvent)  // TS2345
```

## 2.5 常见踩坑

| 问题 | 症状 | 解决 |
|------|------|------|
| `satisfies` 用在 emit | TS2345 缺 type | 直接传 payload，靠签名注入 |
| 循环里 useEffect | Hook 顺序错 | 抽出子组件 |
| 列表 key 用 index | 渲染异常 | 用稳定 ID |
| tsx 测试找不到 `@main/*` | 路径别名失败 | 显式 `--tsconfig tsconfig.node.json` |
| 类未 export | 测试无法 import | 加 `export` 关键字 |
| Monaco 隐式 any | TS strict 失败 | 显式 `typeof import('monaco-editor')` |

# 第 3 篇：Tailwind CSS v4 升级要点

## 3.1 v3 vs v4 核心差异

| 项 | v3 | v4（项目用） |
|----|----|----|
| 配置 | `tailwind.config.js` | `@theme` 块（CSS 内） |
| 引入 | `@tailwind base/components/utilities` | `@import "tailwindcss"` 一行 |
| PostCSS | `tailwindcss` + `autoprefixer` | `@tailwindcss/postcss` |
| 颜色变量 | `theme.extend.colors` | CSS 变量 + `@theme` |
| 暗黑模式 | `darkMode: 'class'` | 同上（兼容） |

## 3.3 在组件中用 CSS 变量

```tsx
// ✅ 用 CSS 变量（可重命名 + 暗黑模式自适应）
<div className="bg-[var(--color-primary)] text-[var(--color-text)]">
  Hello
```

## 3.4 常见踩坑

| 问题 | 症状 | 解决 |
|------|------|------|
| 混用 v3/v4 | 类名失效 | v4 用 `@theme` |
| 硬编码 `#xxxxxx` | 违反硬约束 | 必须用 `var(--color-*)` |
| 任意值 `bg-[#fff]` | 不可重命名 | `bg-[var(--color-bg)]` |
| `safelist` 失效 | 动态类名丢失 | v4 自动检测，无需 safelist |

# 第 5 篇：better-sqlite3 本地持久化

## 5.1 启动配置（必须）

```typescript
// src/main/services/db/database.ts
import Database from 'better-sqlite3'
import path from 'node:path'

const db = new Database(path.join(userDataPath, 'app.db'))

// ✅ WAL 模式（提升并发读）
db.pragma('journal_mode = WAL')
// ✅ 启用外键
db.pragma('foreign_keys = ON')
// ✅ 同步模式 NORMAL（性能与安全平衡）
db.pragma('synchronous = NORMAL')

export const rawDb = db  // 暴露原始连接给需要事务的模块
```

## 5.2 参数化查询（防 SQL 注入）

```typescript
// ✅ 用 prepared statement + 参数化
const insertLog = db.prepare(`
  INSERT INTO logs (session_id, level, message, created_at)
  VALUES (?, ?, ?, ?)
`)
insertLog.run(sessionId, level, message, Date.now())

// ❌ 反模式：字符串拼接
db.exec(`INSERT INTO logs VALUES ('${sessionId}', ...)`)  // SQL 注入！
```

## 5.3 事务（better-sqlite3 是同步的）

```typescript
// ✅ 同步事务
const insertMany = db.transaction((items: LogItem[]) => {
  for (const item of items) {
    insertLog.run(item.sessionId, item.level, item.message, item.timestamp)
  }
})
insertMany(logs)  // 同步执行，原子性保证

// ❌ 反模式：在事务里 await
await db.transaction(async () => {  // 错！better-sqlite3 不支持
  await someAsyncOp()
})
```

## 5.4 索引与查询

```sql
-- ✅ 为高频查询字段建索引
CREATE INDEX idx_logs_session_id ON logs(session_id);
CREATE INDEX idx_logs_created_at ON logs(created_at);

-- ✅ EXPLAIN QUERY PLAN 检查
EXPLAIN QUERY PLAN SELECT * FROM logs WHERE session_id = ?;
-- 应出现 USING INDEX idx_logs_session_id
```

## 5.5 常见踩坑

| 问题 | 症状 | 解决 |
|------|------|------|
| 字符串拼接 SQL | 注入风险 | 必用 `?` 参数化 |
| 事务里 `await` | 边界错误 | better-sqlite3 是同步的 |
| 没开 WAL | 并发阻塞 | 启动时 PRAGMA |
| 没开外键 | 外键不生效 | 启动时 PRAGMA |
| 主线程长查询 | UI 卡顿 | Worker 线程（v1.0 暂不实施） |

# 第 6 篇：Vercel AI SDK + Claude Agent SDK

## 6.1 多 Provider 统一接口

```typescript
// src/main/services/llm/vercel-ai-service.ts
import { generateText, streamText, tool } from 'ai'
import { anthropic } from '@ai-sdk/anthropic'
import { openai } from '@ai-sdk/openai'
import { createOpenAICompatible } from '@ai-sdk/openai'  // 用于国内 Provider

// ✅ Provider 工厂
function getModel(provider: string, modelId: string) {
  switch (provider) {
    case 'anthropic': return anthropic(modelId)
    case 'openai': return openai(modelId)
    case 'volcengine': return createOpenAICompatible({
      name: 'volcengine',
      baseURL: 'https://ark.cn-beijing.volces.com/api/v3',
      apiKey: process.env.VOLCENGINE_API_KEY!,
    })(modelId)
    default: throw new Error(`Unknown provider: ${provider}`)
  }
}
```

## 6.2 Tool Calling

```typescript
// ✅ 用 Zod schema 定义工具
import { tool } from 'ai'
import { z } from 'zod'

const sshExecTool = tool({
  description: '在 SSH 服务器上执行命令',
  parameters: z.object({
    connId: z.string().describe('SSH 连接 ID'),
    command: z.string().describe('Shell 命令'),
  }),
  execute: async ({ connId, command }) => {
    const result = await sshManager.exec(connId, command)
    return { exitCode: result.exitCode, stdout: result.stdout }
  },
})

// 调用
const { text, toolCalls } = await generateText({
  model: getModel('anthropic', 'claude-3-5-sonnet'),
  tools: { sshExec: sshExecTool },
  prompt: '检查磁盘使用率',
  toolChoice: 'auto',  // 让模型决定
})
```

## 6.3 Claude Agent SDK（项目硬约束 R12 三态审批）

```typescript
// src/main/core/agent/claude-sdk/claude-sdk-wrapper.ts
import { ClaudeAgent } from '@anthropic-ai/claude-agent-sdk'

const agent = new ClaudeAgent({
  model: 'claude-3-5-sonnet',
  systemPrompt: '你是 Linux 运维专家...',
  // ✅ 工具白名单（必须显式）
  allowedTools: ['ssh_exec', 'read_file', 'web_search'],
  // ✅ 三态权限审批
  permissionMode: 'always' | 'auto' | 'never',  // ALWAYS/AUTO/NEVER
  // ✅ Token 消耗透明
  onUsage: (usage) => {
    log.info('Token 消耗', { input: usage.input, output: usage.output, cost: usage.cost })
  },
})

// 连续对话
const session = await agent.start('磁盘满了')
const response1 = await session.send('帮我清理')
const response2 = await session.send('确认执行')  // 上下文保持
```

## 6.4 关键注意事项

| 问题 | 症状 | 解决 |
|------|------|------|
| Tool 内递归 LLM | Token 爆炸 | Tool 内不发新推理 |
| System Prompt > 8K | Cache miss | 控制在 8K 内 |
| 不传 `allowedTools` | 无边界 | 必传白名单 |
| 没设 `toolChoice` | 模型不调 | 显式 `'auto'` |
| 混用 Claude CLI + SDK | API 不一致 | 统一用 SDK |
| 不监控 Token 成本 | 预算失控 | `onUsage` 回调 |
| 海外 API 走代理 | 失败 | 默认本地/国内 Provider |

# 第 7 篇：MCP 协议集成

## 7.1 什么是 MCP

Model Context Protocol：让 LLM 调用外部工具的标准化协议。

```
┌──────────┐        ┌──────────┐        ┌──────────┐
│   LLM    │  JSON  │   MCP    │  stdio │   Tool   │
│  Client  │◄──────►│  Server  │◄──────►│  Backend │
└──────────┘  RPC   └──────────┘        └──────────┘
```

## 7.2 在项目中暴露工具

```typescript
// src/main/services/mcp/server.ts
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp'
import { z } from 'zod'

const server = new McpServer({ name: 'tdsf-tools', version: '1.0.0' })

// ✅ 注册一个工具
server.tool(
  'ssh_exec',
  '在 SSH 服务器上执行命令',
  {
    connId: z.string().describe('SSH 连接 ID'),
    command: z.string().describe('Shell 命令'),
  },
  async ({ connId, command }) => {
    const result = await sshManager.exec(connId, command)
    return {
      content: [{ type: 'text', text: JSON.stringify(result) }],
    }
  }
)

// 启动 stdio server
server.startStdio()
```

```typescript
// electron.vite.config.ts
import { defineConfig, externalizeDepsPlugin } from 'electron-vite'
import react from '@vitejs/plugin-react'
import { resolve } from 'path'

export default defineConfig({
  main: {
    plugins: [externalizeDepsPlugin()],
    build: {

      },

    build: {
      rollupOptions: {
        input: { index: resolve(__dirname, 'src/preload/index.ts') },

    },
  },
  renderer: {
```

# 第 10 篇：Python Sidecar 多进程隔离

## 10.1 架构

```
主进程 (TypeScript)
  │
  ├── stdio JSON-RPC ──→ sidecar-a (Python) - drain3 日志模板
  ├── stdio JSON-RPC ──→ sidecar-b (Python) - dowhy 因果推断
  └── stdio JSON-RPC ──→ sidecar-c (Python) - agentscope 多 Agent
```

## 10.2 Sidecar 通信协议

```typescript
// 主进程侧
import { spawn } from 'node:child_process'

const sidecar = spawn('python', ['sidecar-a/main.py'])
sidecar.stdin.write(JSON.stringify({ method: 'drain3.process', params: { lines: [...] } }) + '\n')
sidecar.stdout.on('data', (chunk) => {
  const response = JSON.parse(chunk.toString())
  // { result: { templates: [...] } }
})

// ✅ 健康检查：验证 spawn 的 PID
const pid = sidecar.pid
// 定期 ps -p <pid> 或 tasklist /FI "PID eq <pid>"
```

## 10.3 Sidecar 启动脚本

```bash
# scripts/start-sidecars.sh
#!/bin/bash
cd "$(dirname "$0")/../sidecar-a"
python main.py &
SIDECAR_A_PID=$!
echo "sidecar-a PID: $SIDECAR_A_PID"

cd "$(dirname "$0")/../sidecar-b"
python main.py &
SIDECAR_B_PID=$!

# 写入 PID 文件
echo $SIDECAR_A_PID > /tmp/sidecar-a.pid
echo $SIDECAR_B_PID > /tmp/sidecar-b.pid
```

## 10.4 常见踩坑

| 问题 | 症状 | 解决 |
|------|------|------|
| 端口已占用 | `Address already in use` | 启动前用 `lsof -i` / `netstat` 检查 |
| 跨平台日志关键词 | Windows vs Linux 报错信息不同 | 全覆盖（`winerror 10048` + `Errno 98`） |
| 健康检查只看端口 | 误判进程死锁 | 验证 spawn PID 是否存活 |
| JSON-RPC 解析失败 | timeout | 加 timeout + 重试机制 |
| Python 版本不兼容 | import error | requirements.txt 锁版本 |
